## 8. SQL 版本号排序坑（2026-09-02 发现并修复）

- **现象**：`apply-sql.sh` 原先用 bash glob 顺序执行，导致 `procurement_6x_v10_ai_detail.sql`、`v11`、`v12` 在 `v5~v9` 之前执行。v12 依赖 `invoice_info.ocr_json`，而该列由 v5 创建，于是部署时 v12 报错 `Unknown column 'ocr_json' in 'invoice_info'`，deploy.sh 中断。
- **修复**：`apply-sql.sh` 改用 `sort -V`（version sort），确保 v2~v9 在 v10~v12 之前执行。
- **已提交**：`ruoyi-6x/script/sql/apply-sql.sh`（commit `9d67d4a80`）。
- **待处理**：已同步到服务器；后续新增脚本继续按 `v<数字>_` 命名即可。

## 9. applied-sql.log 与数据库状态可能不一致

- **现象**：本次部署中 `procurement_6x_v10_ai_detail.sql` 已在数据库生效（`pms_acceptance.ai_detail` 存在），但 log 记录和实际执行顺序混乱，导致排查困难。`procurement_role_menu_cleanup.sql` 也在 deploy.sh 中报失败，但手动执行成功。
- **原因**：之前手动执行/调试 SQL 后未同步更新 log，或失败后 log 未回滚。
- **修复**：本次已按数据库实际状态补齐 log。
- **建议**：以后遇到 SQL 失败，先手动执行确认，再同步 log；必要时整库 dump 后重置 log。
