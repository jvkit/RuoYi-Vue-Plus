# 006 - IoC 与依赖注入实战教学

> 目标：通过改造 `sp_demo` 里的用户管理代码，真正理解"为什么用接口"、"为什么用 @Autowired"、"Spring 到底注入了什么"。

---

## 一、上节课的代码回顾

上节课我们写了一个 `UserService`：

```java
@Service
public class UserService {
    // ...
}
```

和一个 `UserController`：

```java
@RestController
public class UserController {
    @Autowired
    private UserService userService;
}
```

这套代码能跑，但在真实项目里，我们**几乎不会直接写一个类然后注入它**，而是：

1. 先定义一个 **接口**（Interface）。
2. 再写一个 **实现类**（Impl）。
3. Controller 里注入的是 **接口**。

这节课就来改造它，并解释为什么。

---

## 二、为什么要用接口

### 2.1 不用接口的问题

假设你直接写：

```java
@Autowired
private UserService userService;
```

如果 `UserService` 是一个普通类，那么 Controller 就**死死地依赖**这个具体类。将来你想换一套实现（比如从内存存储换成数据库存储），就要改 Controller 的代码。

### 2.2 用接口的好处

```java
// Controller 只依赖接口
@Autowired
private UserService userService;
```

```java
// 实现类 A：内存存储
@Service
public class UserServiceMemoryImpl implements UserService { }

// 实现类 B：数据库存储
@Service
public class UserServiceDbImpl implements UserService { }
```

Controller 不需要知道具体是哪个实现，Spring 会按规则选一个合适的实现注入进来。要换实现？只需要改实现类上的注解，或者加个 `@Primary` / `@Qualifier`，Controller 一行不用动。

**这就是"面向接口编程"，也是 Spring 项目的标准写法。**

## 三、改造 UserService：从类到接口 + 实现

### 3.1 定义接口

新建 `UserService.java`（接口）：

```java
package cn.jvkit.spdemo.service;

import cn.jvkit.spdemo.entity.User;
import java.util.List;

public interface UserService {
    List<User> list();
    User getById(Long id);
    Long add(User user);
    void update(Long id, User user);
    void delete(Long id);
}
```

接口里只有方法签名，没有具体实现。它就像一份合同："谁实现我，就必须提供这 5 个方法"。

### 3.2 实现类

新建 `UserServiceImpl.java`：

```java
package cn.jvkit.spdemo.service.impl;

import cn.jvkit.spdemo.entity.User;
import cn.jvkit.spdemo.service.UserService;
import org.springframework.stereotype.Service;

import java.util.*;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicLong;

@Service
public class UserServiceImpl implements UserService {

    private final Map<Long, User> userStore = new ConcurrentHashMap<>();
    private final AtomicLong idGenerator = new AtomicLong(2);

    public UserServiceImpl() {
        userStore.put(1L, new User(1L, "张三", 20));
        userStore.put(2L, new User(2L, "李四", 25));
    }

    @Override
    public List<User> list() {
        return new ArrayList<>(userStore.values());
    }

    @Override
    public User getById(Long id) {
        return userStore.get(id);
    }

    @Override
    public Long add(User user) {
        Long id = idGenerator.incrementAndGet();
        user.setId(id);
        userStore.put(id, user);
        return id;
    }

    @Override
    public void update(Long id, User user) {
        user.setId(id);
        userStore.put(id, user);
    }

    @Override
    public void delete(Long id) {
        userStore.remove(id);
    }
}
```

注意：
- `implements UserService`：表示这个类实现了接口。
- `@Override`：表示下面的方法是重写接口里的方法。
- 类名后面加 `Impl` 是 Java 项目的习惯，表示"实现类"。

### 3.3 Controller 改造

```java
@RestController
@RequestMapping("/users")
public class UserController {

    @Autowired
    private UserService userService;  // 注意：这里现在是接口！

    // ... 方法不变
}
```

## 四、@Autowired 的三种注入方式

Spring 注入依赖有三种写法，推荐使用第三种。

### 4.1 字段注入（Field Injection）—— 我们之前用的

```java
@Autowired
private UserService userService;
```

优点：代码少。  
缺点：不方便单元测试，依赖关系不直观。  
**真实项目中不太推荐，但 RuoYi 项目里大量在用，所以你也要会看。**

### 4.2 Setter 注入

```java
private UserService userService;

@Autowired
public void setUserService(UserService userService) {
    this.userService = userService;
}
```

优点：可选依赖，可以在运行中替换。  
缺点：代码啰嗦。  
**很少用。**

### 4.3 构造方法注入（Constructor Injection）—— 推荐

```java
@RestController
@RequestMapping("/users")
public class UserController {

    private final UserService userService;

    // Spring 会自动调用这个构造方法，把 UserService 的实现类传进来
    public UserController(UserService userService) {
        this.userService = userService;
    }
}
```

优点：
- 依赖明确，一眼就能看出这个类需要什么。
- `final` 修饰后，对象创建后就不能被修改，更安全。
- 方便单元测试。

**Spring 官方推荐。新版 Spring Boot 如果只有一个构造方法，甚至可以省略 `@Autowired`。**

## 五、如果有多个实现类怎么办

假设你又写了一个实现：

```java
@Service
public class UserServiceV2Impl implements UserService {
    // 另一种实现
}
```

Spring 发现 `UserService` 有两个实现，不知道该注入哪个，就会报错。

### 5.1 方案一：@Primary（优先使用）

在默认实现上加 `@Primary`：

```java
@Service
@Primary
public class UserServiceImpl implements UserService {
    // ...
}
```

Spring 会优先选这个。

### 5.2 方案二：@Qualifier（指定名字）

```java
@Autowired
@Qualifier("userServiceV2Impl")  // 注意：首字母小写
private UserService userService;
```

`@Qualifier` 里写的是**实现类的 Bean 名称**。Spring 默认会把类名首字母小写作为 Bean 名：

- `UserServiceImpl` → `userServiceImpl`
- `UserServiceV2Impl` → `userServiceV2Impl`

### 5.3 方案三：直接用实现类类型

```java
@Autowired
private UserServiceImpl userService;
```

不推荐使用，因为这样又耦合到具体实现类了。

## 六、Spring 到底创建了几个对象

Spring 默认把 `@Service`、`@Component`、`@RestController` 标记的类创建成**单例（Singleton）**：整个应用运行期间，每个类只创建一个对象，放在 IoC 容器里。

所以：

- `UserServiceImpl` 只创建 1 个。
- `UserController` 只创建 1 个。
- `UserController` 里的 `userService` 指向的就是那唯一的 `UserServiceImpl` 对象。

**验证方法**：在 `UserServiceImpl` 的构造方法里打印一行日志，你会发现启动时只打印一次。
