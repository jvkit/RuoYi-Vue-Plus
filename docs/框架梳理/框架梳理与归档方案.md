核心自定义表：
- `pms_project`：项目树
- `pms_procurement_request(_item)`：采购申请
- `pms_purchase_order(_item)`：采购订单
- `pms_acceptance(_item)`：采购验收
- `pms_warehouse_stock`：仓库库存
- `pms_issue_request`：领用申请
- `pms_bom_product/part/item`：BOM
- `pms_fund_flow`：资金流水

## 四、后续扩展方向

### 4.1 近期（1–2 个月）

1. **权限体系完善**
   - 当前：功能权限已放开给普通用户，数据权限未隔离。
   - 目标：按角色/项目/组织做数据范围过滤。

2. **BOM 模块落地**
   - 单页 BOM 管理：产品 → 部件 → 零件。
   - 与仓库联动、缺料单生成、一键转采购申请。

3. **发票管理迁移到 6.x**
   - 将 5.x 的 `ruoyi-invoice` 迁移到 `ruoyi-6x`。
   - 前端 `views/invoice` 迁移到 `plus-ui-6x`。

4. **采购申请优化**
   - 科研/非科研分类树形选择。
   - 项目资金校验。
   - 审批流稳定（当前已有项目负责人 + 金额分支）。

### 4.2 中期（3–6 个月）

1. **AI 能力接入**
   - 从 ~/workspace/owu-feed/gateway 复用 OCR/嵌入模型能力。
   - 发票 AI 识别/审核。
   - BOM 字段智能补全。
   - 采购链接自动抓取型号价格（Agent + 浏览器）。

2. **仓库与出入库完整闭环**
   - 验收入库、领用出库、库存预警。
   - 与 BOM 的联动查询。

3. **合同与报销**
   - 合同模板填充。
   - 报销材料打包导出。

### 4.3 长期（6 个月以上）

1. **中心 OA 对接（泛微）**
   - 对话式完成中心 OA 流程。

2. **移动端完整化**
   - 不仅验收，还包括采购申请、领用、审批等。

3. **多组织/多租户**
   - 6.x 已去多租户，若未来需要多部门独立核算，需重新评估。

## 五、技术债务与清理清单

| 问题 | 影响 | 建议处理 |
|---|---|---|
| 5.x 目录占用根目录 | 新开发者混淆 | 归档到 `archive/` |

| 启动脚本端口检查偶发误判 | 前端未就绪即报错 | 优化等待逻辑 |
