# 14-代码生成器到底能干啥、怎么用

## 1. 代码生成器是干嘛的？

**代码生成器 = 自动帮你写前后端 CRUD 代码。**

你只要告诉它：

- 数据库里哪张表。
- 每个字段是什么含义。
- 哪些字段要在列表显示、哪些要搜索、哪些是下拉框。

它就能生成：

- 后端：Entity、Bo、Vo、Mapper、Service、Controller、XML。
- 前端：API、Types、Vue 页面。
- SQL：菜单和按钮权限。

然后你把生成的代码复制到项目里，稍微改改就能用。

---

## 2. 代码生成器不是万能的

它适合的场景：

- 单表 CRUD（增删改查、分页、导出）。
- 字段类型比较常规（字符串、数字、日期、字典值）。
- 业务逻辑简单，不需要复杂计算和流程。

它不适合的场景：

- 多表关联查询。
- 复杂业务逻辑（比如自动计算价税合计、工作流审批）。
- 高度自定义的 UI。

所以你说「代码生成器没啥用」也不完全对：**对于标准 CRUD，它能省 70% 的代码量；对于复杂业务，它只能生成一个骨架，剩下要手写。**

---

## 3. 完整使用流程

### 第 1 步：先建好数据库表

比如要做一个「会议室预定」模块，先建表：

```sql
CREATE TABLE meeting_room_booking (
  id bigint PRIMARY KEY,
  room_name varchar(100) NOT NULL COMMENT '会议室名称',
  booking_date date COMMENT '预定日期',
  start_time datetime COMMENT '开始时间',
  end_time datetime COMMENT '结束时间',
  booking_user varchar(50) COMMENT '预定人',
  status varchar(20) DEFAULT 'pending' COMMENT '状态',
  remark varchar(500) COMMENT '备注',
  create_by bigint,
  create_time datetime,
  update_by bigint,
  update_time datetime,
  del_flag char(1) DEFAULT '0'
);
```

### 第 2 步：进入代码生成器

```
系统工具 → 代码生成
```

### 第 3 步：导入表

点击「导入」按钮，弹窗里会列出数据库里所有表。

勾选 `meeting_room_booking`，点确定。

### 第 4 步：编辑表信息

导入后，在列表里找到这张表，点「编辑」。

这里有三个 tab：

#### 4.1 基本信息

| 字段 | 填写 |
|---|---|
| 表名称 | `meeting_room_booking` |
| 表描述 | 会议室预定 |
| 实体类名称 | `MeetingRoomBooking` |
| 作者 | 你的名字 |
| 生成包路径 | `org.dromara.meeting` |
| 生成模块名 | `meeting` |
| 生成业务名 | `booking` |

#### 4.2 字段信息（最重要）

每一列可以配置：

| 配置项 | 含义 |
|---|---|
| 字段描述 | 中文名，会显示在表格列头 |
| 物理类型 | 数据库类型 |
| Java类型 | `String`、`Long`、`Date`、`BigDecimal` 等 |
| Java属性 | 驼峰字段名 |
| 插入 | 新增时是否显示 |
| 编辑 | 修改时是否显示 |
| 列表 | 表格里是否显示 |
| 查询 | 是否作为搜索条件 |
| 查询方式 | `=`、`LIKE`、`BETWEEN` 等 |
| 显示类型 | 输入框、下拉框、日期选择器等 |
| 字典类型 | 如果是下拉框，绑定哪个字典 |

比如 `status` 字段：

- 显示类型：`下拉框`
- 字典类型：`meeting_booking_status`（你需要先在字典管理里建）
- 列表：勾选
- 查询：勾选

#### 4.3 生成信息

确认生成路径、包名、模块名没问题就行。

### 第 5 步：预览代码

点「预览」，可以看到生成的每个文件内容。

### 第 6 步：生成代码

点「生成」，会下载一个 zip 文件。

### 第 7 步：把代码复制到项目

解压 zip，里面大概有这些文件：

```
meeting/
├── main/java/org/dromara/meeting/
│   ├── controller/MeetingRoomBookingController.java
│   ├── domain/MeetingRoomBooking.java
│   ├── domain/bo/MeetingRoomBookingBo.java
│   ├── domain/vo/MeetingRoomBookingVo.java
│   ├── mapper/MeetingRoomBookingMapper.java
│   ├── service/IMeetingRoomBookingService.java
│   └── service/impl/MeetingRoomBookingServiceImpl.java
├── main/resources/mapper/meeting/MeetingRoomBookingMapper.xml
└── sql/meeting_booking_menu.sql
```

把这些文件按路径复制到 `RuoYi-Vue-Plus/ruoyi-modules/ruoyi-meeting/`（如果没有这个模块，先新建）。

前端代码也类似复制到 `plus-ui/src/`。

### 第 8 步：注册模块、执行菜单 SQL、编译

和手动开发模块一样的步骤：

1. 注册 Maven 模块。
2. 执行生成的菜单 SQL。
3. 前端 `pnpm build:prod`、后端 `mvn package`。
4. 部署、测试。

## 4. 代码生成器的真正价值

| 手动写 | 代码生成器生成 |
|---|---|
| Entity、Bo、Vo 各一个文件 | ✅ 自动生成 |
| Mapper 接口和 XML | ✅ 自动生成 |
| Service 接口和实现 | ✅ 自动生成 |
| Controller 增删改查 | ✅ 自动生成 |
| 前端 API 和页面 | ✅ 自动生成 |
| 菜单权限 SQL | ✅ 自动生成 |
| 复杂的业务逻辑 | ❌ 需要手写 |
| 多表关联 | ❌ 需要手写 |
| 工作流接入 | ❌ 需要手写 |

---

## 5. 什么时候用代码生成器？

建议：

- **标准 CRUD 模块**：直接用代码生成器，生成后微调。
- **复杂模块**：先用代码生成器生成基础骨架，再手写业务逻辑。
- **学习阶段**：像发票管理这种，建议先手写一遍理解分层，然后再用代码生成器复刻，对比差异。

---

## 6. 总结

代码生成器不是「一键完成所有功能」，而是「一键完成 70% 的重复代码」。

对于你们现在要扩展的 OA 模块（报销、会议室、考勤等），很多都可以用代码生成器打底，然后再根据业务规则修改 Service 和前端页面。
