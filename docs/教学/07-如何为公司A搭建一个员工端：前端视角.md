# 07-如何为公司 A 搭建一个员工端：前端视角

## 0. 先说结论

RuoYi-Vue-Plus 官方前端 `plus-ui` 本质上是一个**管理后台界面**（admin console），风格偏复杂、菜单多、信息量密集，**不太适合直接给普通员工当日常办公入口**。

实际项目里通常有两种做法：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **方案 1：复用 plus-ui，只给员工看少数菜单** | 给员工账号只分配员工相关菜单，隐藏所有管理模块 | 快，一套代码，省维护 | UI 还是 admin 风格，员工体验一般 |
| **方案 2：另写一个员工端前端** | 用 Vue3 再起一个项目，调用同一套后端接口 | 体验好，可以按需设计，品牌形象强 | 工作量多一套前端 |

**推荐路径**：

> 先用方案 1 把公司 A 的员工权限、菜单、流程跑通；等业务稳定后，再考虑方案 2 做一个更轻量的员工门户。

下面按这个思路展开。

---

## 1. 员工端和管理后台的区别

不要试图让「管理员后台」和「员工工作台」长一模一样，它们的使用场景不同：

| | 管理后台（admin） | 员工工作台（employee portal） |
|---|---|---|
| 使用者 | IT 管理员、HR、财务、领导 | 普通员工 |
| 核心诉求 | 配置、监管、统计、权限 | 快速提交、查看进度、处理待办 |
| 界面风格 | 左侧多级菜单、表格密集、字段多 | 简洁、卡片式、步骤清晰 |
| 菜单数量 | 几十个 | 通常 3~7 个 |

所以给员工用，关键是**菜单要少、操作要直、流程要顺**。

---

## 2. 方案 1：复用 plus-ui，只给员工看需要的菜单

这是最快的方式，适合 MVP（最小可用版本）。

### 2.1 给员工设计一个角色

进入：

```
系统管理 → 角色管理
```

新建角色：**公司 A 员工**。

只给它分配这些权限：

```text
# 工作流相关
workflow:leave:list/add        # 请假申请
workflow:task:waiting          # 我的待办
workflow:instance:currentList  # 我发起的
workflow:task:finish           # 我的已办

# 采购相关
workflow:procurement:list/add  # 采购申请

# 发票相关
invoice:info:list/add          # 发票上传
```

不分配：

```text
system:user:*        # 用户管理
system:role:*        # 角色管理
system:menu:*        # 菜单管理
system:dict:*        # 字典管理
system:monitor:*     # 系统监控
system:tool:*        # 系统工具
```

### 2.2 给员工账号分配这个角色

进入：

```
系统管理 → 用户管理
```

新增用户，归属部门，角色选择「公司 A 员工」。

### 2.3 员工登录后会看到什么？

由于角色只配置了少量菜单权限，员工登录后左侧菜单会自动过滤，只能看到：

```
工作流
  ├── 请假申请
  ├── 我的待办
  ├── 我发起的
  └── 我的已办
采购管理
  └── 采购申请
发票管理
  └── 发票信息
```

admin 看到的管理菜单，员工都看不到。

### 2.4 但 UI 还是 admin 风格怎么办？

`plus-ui` 支持一定程度的美化：

| 修改项 | 位置 |
|---|---|
| 系统标题、Logo | `plus-ui/.env.production` 里的 `VITE_APP_TITLE`、`VITE_APP_LOGO_TITLE` |
| 登录页 Logo | `plus-ui/src/assets/images/login-logo.png` 等 |
| 主题色 | `plus-ui/src/layout/components/Settings/index.vue` 或主题配置文件 |
| 侧边栏风格 | 设置里的「布局设置」：经典、横向、混合 |

这些改完后，看起来会稍微像公司自己的系统，但**整体结构还是 admin 后台**。

### 2.5 方案 1 的优缺点总结

- ✅ 最快 1~2 天就能让员工用。
- ✅ 后端接口、权限、流程都现成的。
- ❌ 员工体验还是偏复杂。
- ❌ 登录页、菜单结构一看就是管理系统。

## 3. 方案 2：另写一个员工端前端

如果对公司 A 来说，员工体验很重要，建议另起一个前端项目。

### 3.1 这个员工端长什么样？

可以给员工端设计一个完全不同的界面，比如：

```
顶部：公司 A Logo + 员工姓名 + 退出
中间：工作台（卡片式）
  ├── 📝 提交申请
  │     ├── 请假
  │     ├── 采购
  │     └── 发票上传
  ├── 📋 我的待办（3 条）
  ├── 📄 我发起的
  └── ⚙️ 个人中心
```

底部可以放一些快捷入口、通知公告。

### 3.2 技术选型

由于后端接口已经是 RuoYi 的，员工端前端可以任选：

| 选型 | 说明 |
|---|---|
| **继续用 Vue3 + TS + Element Plus** | 和 plus-ui 技术栈一致，团队学习成本低 |
| **Vben Admin / Ant Design Vue** | 组件更丰富，适合复杂员工端 |
| **自己写纯 Vue3 + Tailwind CSS** | 最灵活，可以完全自定义 UI |
| **做成移动端 H5 / 微信小程序** | 如果员工主要在手机上用 |

### 3.3 员工端需要对接哪些后端接口？

RuoYi 后端已经提供了这些接口，员工端直接调用即可：

| 功能 | 后端接口 |
|---|---|
| 登录 | `POST /auth/login` |
| 获取用户信息 | `GET /system/user/getInfo` |
| 获取菜单 | `GET /system/menu/getRouters`（或自己写简化菜单） |
| 提交请假 | 工作流 leave 相关接口 |
| 提交采购 | `/workflow/procurement` 相关接口 |
| 上传发票 | `/invoice/info` 相关接口 |
| 获取待办 | 工作流 task 相关接口 |

### 3.4 需要注意的点

- **登录加密**：RuoYi 的登录接口有 RSA + AES 加密，员工端需要复刻这套加密逻辑，或者直接找后端临时关掉加密（内部系统可以这样做）。
- **token 机制**：用的是 Sa-Token，员工端登录后保存 `access_token`，每次请求带 `Authorization: Bearer token` 和 `clientid` 头。
- **菜单简化**：员工端不需要动态菜单，可以前端写死几个入口。

### 3.5 方案 2 的优缺点总结

- ✅ 体验好，完全按员工场景设计。
- ✅ 可以做出公司 A 的品牌感。
- ❌ 需要单独维护一套前端。
- ❌ 需要处理登录、加密、权限等通用逻辑。

## 4. 针对「公司 A」的推荐落地步骤

假设你现在就想让公司 A 的员工先用起来，建议按这个顺序：

### 第 1 步：明确公司 A 的员工需要哪些功能

先不要写代码，先列需求：

```text
公司 A 员工端 v1.0：
1. 登录
2. 提交请假申请
3. 提交采购申请
4. 上传发票
5. 查看我的待办（审批）
6. 查看我发起的流程进度
7. 查看个人信息
```

### 第 2 步：创建租户和基础数据

```text
系统管理 → 租户管理 → 新增公司 A
系统管理 → 部门管理 → 给公司 A 建部门
系统管理 → 岗位管理 → 给公司 A 建岗位
```

### 第 3 步：创建员工角色

```text
角色名：公司 A 员工
权限：
  - 请假申请相关
  - 采购申请相关
  - 发票上传相关
  - 我的待办 / 我发起的
```

### 第 4 步：创建测试员工账号

```text
系统管理 → 用户管理 → 新增
用户名：zhangsan
角色：公司 A 员工
租户：公司 A
```

### 第 5 步：选择前端方案

- 如果急，**直接用 plus-ui**，登录后只看员工菜单。
- 如果要体验好，**另起一个员工端项目**。

### 第 6 步：跑通一个最小闭环

以「员工提交请假 → 主管审批 → 员工查看结果」为第一个闭环。

跑通后，再逐步加采购、发票等模块。

---

## 5. 关于「RuoYi 丑不丑」

`plus-ui` 默认是 Element Plus 的经典 admin 风格，确实比较通用，不算现代。但：

- 它是功能完整的后台，不是设计系统。
- 它的价值在于「权限、菜单、用户、流程、代码生成」这些底层能力。
- UI 是可以改的，但改admin风格有上限。

**建议**：

- 管理员后台继续用 plus-ui（或换 Vben5 / Soybean 等成员前端）。
- 员工端根据预算决定：预算少就改造 plus-ui，预算够就另写一套。

## 6. 总结

| 问题 | 建议 |
|---|---|
| 直接给员工用 plus-ui 吗？ | 可以，但体验一般；适合快速验证 |
| 一般项目怎么做？ | admin 用 plus-ui，员工端另写轻量前端 |
| 公司 A 第一步做什么？ | 创建租户、角色、员工账号，只分配员工菜单 |
| 员工端需要哪些功能？ | 提交申请、处理待办、查看进度、上传发票 |
| UI 太丑怎么办？ | 先改主题色/Logo，后期再决定是否另做员工端 |
