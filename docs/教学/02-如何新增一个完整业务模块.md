# 02-如何新增一个完整业务模块（以「发票管理」为例）

> 目标：在 RuoYi-Vue-Plus 里从零增加一个「发票管理」模块，包含建表、后端 CRUD、前端页面、菜单权限，最终能在浏览器里登录、点侧边栏、增删改查发票。
>
> 本文只写一次，后续补充会另开新文档。

---

## 1. 最终效果

登录 `http://<你的IP>/index`（默认账号 `admin` / `admin123`）后，左侧菜单会出现：

```
发票管理
  └── 发票信息
```

进入页面后可以看到搜索、新增、修改、删除、导出按钮，以及分页列表。

后端接口前缀为 `/invoice/info`，权限标识为 `invoice:info:*`。

---

## 2. 总体思路

一个完整模块通常要动 4 个地方：

1. **数据库**：新增业务表。
2. **后端**：新建一个 Maven 子模块，写 `domain / mapper / service / controller`。
3. **前端**：新增 API 文件 + Vue 页面。
4. **系统配置**：插入字典、菜单、按钮权限 SQL。

RuoYi-Vue-Plus 的菜单由 `sys_menu` 表驱动，但页面组件必须真实存在于 `plus-ui/src/views` 中。因此「后端配菜单」和「前端写页面」缺一不可。

## 3. 数据库表设计

### 3.1 建表语句

本次新增表 `invoice_info`，字段覆盖发票常见信息：

```sql
CREATE TABLE IF NOT EXISTS `invoice_info` (
  `id` bigint NOT NULL COMMENT '主键id',
  `tenant_id` varchar(20) DEFAULT '000000' COMMENT '租户编号',
  `invoice_code` varchar(50) DEFAULT NULL COMMENT '发票代码',
  `invoice_number` varchar(50) NOT NULL COMMENT '发票号码',
  `invoice_type` varchar(20) DEFAULT 'normal' COMMENT '发票类型（normal普票/special专票/electronic电子发票）',
  `amount` decimal(18,2) DEFAULT NULL COMMENT '不含税金额',
  `tax_amount` decimal(18,2) DEFAULT NULL COMMENT '税额',
  `total_amount` decimal(18,2) DEFAULT NULL COMMENT '价税合计',
  `invoice_date` date DEFAULT NULL COMMENT '开票日期',
  `seller_name` varchar(255) DEFAULT NULL COMMENT '销售方名称',
  `buyer_name` varchar(255) DEFAULT NULL COMMENT '购买方名称',
  `status` varchar(20) DEFAULT 'draft' COMMENT '状态（draft草稿/submitted已提交/approved已认证/rejected已驳回）',
  `remark` varchar(500) DEFAULT NULL COMMENT '备注',
  `create_dept` bigint DEFAULT NULL COMMENT '创建部门',
  `create_by` bigint DEFAULT NULL COMMENT '创建者',
  `create_time` datetime DEFAULT NULL COMMENT '创建时间',
  `update_by` bigint DEFAULT NULL COMMENT '更新者',
  `update_time` datetime DEFAULT NULL COMMENT '更新时间',
  `del_flag` char(1) DEFAULT '0' COMMENT '删除标志（0代表存在 2代表删除）',
  PRIMARY KEY (`id`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='发票信息表';
```

> 说明：
> - `id` 不需要 `AUTO_INCREMENT`，框架默认用 MyBatis-Plus 的雪花算法（`ASSIGN_ID`）。
> - 多租户字段 `tenant_id` 和业务审计字段（`create_by` 等）直接从 `BaseEntity` 继承。
> - `del_flag` 为逻辑删除标志，框架常量里 `0` 表示存在、`2` 表示删除。


#### domain/bo/InvoiceInfoBo.java

Bo（Business Object）用于接收前端参数、作为查询条件，并支持校验分组 `AddGroup` / `EditGroup`：

```java
@Data
@EqualsAndHashCode(callSuper = true)
@AutoMapper(target = InvoiceInfo.class, reverseConvertGenerate = false)
public class InvoiceInfoBo extends BaseEntity {

    @NotNull(message = "主键不能为空", groups = {EditGroup.class})
    private Long id;

    private String invoiceCode;

    @NotBlank(message = "发票号码不能为空", groups = {AddGroup.class, EditGroup.class})
    private String invoiceNumber;

    @NotBlank(message = "发票类型不能为空", groups = {AddGroup.class, EditGroup.class})
    private String invoiceType;

    private BigDecimal amount;
    private BigDecimal taxAmount;
    private BigDecimal totalAmount;

    @DateTimeFormat(pattern = "yyyy-MM-dd")
    @JsonFormat(pattern = "yyyy-MM-dd")
    private Date invoiceDate;

    private String sellerName;
    private String buyerName;
    private String status;
    private String remark;
}
```

> `@AutoMapper(target = InvoiceInfo.class)` 是 MapStruct 自动转换注解，`MapstructUtils.convert(bo, InvoiceInfo.class)` 即可互转。

#### domain/vo/InvoiceInfoVo.java

Vo（View Object）用于返回给前端列表/详情，结构和 Bo 类似，通常去掉校验注解。

### 4.4 Service 层

#### service/IInvoiceInfoService.java

```java
public interface IInvoiceInfoService {
    InvoiceInfoVo queryById(Long id);
    TableDataInfo<InvoiceInfoVo> queryPageList(InvoiceInfoBo bo, PageQuery pageQuery);
    List<InvoiceInfoVo> queryList(InvoiceInfoBo bo);
    InvoiceInfoVo insertByBo(InvoiceInfoBo bo);
    InvoiceInfoVo updateByBo(InvoiceInfoBo bo);
    Boolean deleteWithValidByIds(List<Long> ids);
}
```

#### service/impl/InvoiceInfoServiceImpl.java

核心逻辑：

```java
@RequiredArgsConstructor
@Service
public class InvoiceInfoServiceImpl implements IInvoiceInfoService {

    private final InvoiceInfoMapper baseMapper;

    @Override
    public TableDataInfo<InvoiceInfoVo> queryPageList(InvoiceInfoBo bo, PageQuery pageQuery) {
        LambdaQueryWrapper<InvoiceInfo> lqw = buildQueryWrapper(bo);
        Page<InvoiceInfoVo> result = baseMapper.selectVoPage(pageQuery.build(), lqw);
        return TableDataInfo.build(result);
    }

    private LambdaQueryWrapper<InvoiceInfo> buildQueryWrapper(InvoiceInfoBo bo) {
        LambdaQueryWrapper<InvoiceInfo> lqw = Wrappers.lambdaQuery();
        lqw.like(StringUtils.isNotBlank(bo.getInvoiceNumber()), InvoiceInfo::getInvoiceNumber, bo.getInvoiceNumber());
        lqw.like(StringUtils.isNotBlank(bo.getSellerName()), InvoiceInfo::getSellerName, bo.getSellerName());
        lqw.like(StringUtils.isNotBlank(bo.getBuyerName()), InvoiceInfo::getBuyerName, bo.getBuyerName());
        lqw.eq(StringUtils.isNotBlank(bo.getInvoiceType()), InvoiceInfo::getInvoiceType, bo.getInvoiceType());
        lqw.eq(StringUtils.isNotBlank(bo.getStatus()), InvoiceInfo::getStatus, bo.getStatus());
        lqw.orderByDesc(BaseEntity::getCreateTime);
        return lqw;
    }

    @Override
    public InvoiceInfoVo insertByBo(InvoiceInfoBo bo) {
        // 自动计算价税合计
        if (bo.getAmount() != null && bo.getTaxAmount() != null) {
            bo.setTotalAmount(bo.getAmount().add(bo.getTaxAmount()));
        }
        // 默认草稿状态
        if (StringUtils.isBlank(bo.getStatus())) {
            bo.setStatus(BusinessStatusEnum.DRAFT.getStatus());
        }
        InvoiceInfo add = MapstructUtils.convert(bo, InvoiceInfo.class);
        baseMapper.insert(add);
        bo.setId(add.getId());
        return MapstructUtils.convert(add, InvoiceInfoVo.class);
    }

    @Override
    public InvoiceInfoVo updateByBo(InvoiceInfoBo bo) {
        if (bo.getAmount() != null && bo.getTaxAmount() != null) {
            bo.setTotalAmount(bo.getAmount().add(bo.getTaxAmount()));
        }
        InvoiceInfo update = MapstructUtils.convert(bo, InvoiceInfo.class);
        baseMapper.updateById(update);
        return MapstructUtils.convert(update, InvoiceInfoVo.class);
    }

    @Override
    public Boolean deleteWithValidByIds(List<Long> ids) {
        return baseMapper.deleteByIds(ids) > 0;
    }
}
```

> 这里演示了在 Service 里做简单业务计算：`totalAmount = amount + taxAmount`。如果是复杂校验，也可以放在这里。

### 4.5 Controller 层

#### controller/InvoiceInfoController.java

```java
@Validated
@RequiredArgsConstructor
@RestController
@RequestMapping("/invoice/info")
public class InvoiceInfoController extends BaseController {

    private final IInvoiceInfoService invoiceInfoService;

    @SaCheckPermission("invoice:info:list")
    @GetMapping("/list")
    public TableDataInfo<InvoiceInfoVo> list(InvoiceInfoBo bo, PageQuery pageQuery) {
        return invoiceInfoService.queryPageList(bo, pageQuery);
    }

    @SaCheckPermission("invoice:info:export")
    @Log(title = "发票信息", businessType = BusinessType.EXPORT)
    @PostMapping("/export")
    public void export(InvoiceInfoBo bo, HttpServletResponse response) {
        List<InvoiceInfoVo> list = invoiceInfoService.queryList(bo);
        ExcelUtil.exportExcel(list, "发票信息", InvoiceInfoVo.class, response);
    }

    @SaCheckPermission("invoice:info:query")
    @GetMapping("/{id}")
    public R<InvoiceInfoVo> getInfo(@NotNull(message = "主键不能为空") @PathVariable Long id) {
        return R.ok(invoiceInfoService.queryById(id));
    }

    @SaCheckPermission("invoice:info:add")
    @Log(title = "发票信息", businessType = BusinessType.INSERT)
    @RepeatSubmit()
    @PostMapping()
    public R<InvoiceInfoVo> add(@Validated(AddGroup.class) @RequestBody InvoiceInfoBo bo) {
        return R.ok(invoiceInfoService.insertByBo(bo));
    }

    @SaCheckPermission("invoice:info:edit")
    @Log(title = "发票信息", businessType = BusinessType.UPDATE)
    @RepeatSubmit()
    @PutMapping()
    public R<InvoiceInfoVo> edit(@Validated(EditGroup.class) @RequestBody InvoiceInfoBo bo) {
        return R.ok(invoiceInfoService.updateByBo(bo));
    }

    @SaCheckPermission("invoice:info:remove")
    @Log(title = "发票信息", businessType = BusinessType.DELETE)
    @DeleteMapping("/{ids}")
    public R<Void> remove(@NotEmpty(message = "主键不能为空") @PathVariable Long[] ids) {
        return toAjax(invoiceInfoService.deleteWithValidByIds(List.of(ids)));
    }
}
```

关键注解说明：

- `@SaCheckPermission("invoice:info:list")`：Sa-Token 权限校验，对应菜单/按钮的 `perms` 字段。
- `@Log(title = "发票信息", businessType = ...)`：记录操作日志。
- `@RepeatSubmit()`：防止重复提交。
- `@Validated(AddGroup.class)`：新增时只校验 `AddGroup` 分组字段。

### 5.3 页面组件

#### views/invoice/info/index.vue

```ts
import { listInvoiceInfo, getInvoiceInfo, addInvoiceInfo, updateInvoiceInfo, delInvoiceInfo, exportInvoiceInfo } from '@/api/invoice/info';
```

```bash

  -H 'Content-Type: application/json' \
```

```bash
  -H "Authorization: Bearer $TOKEN" \
  -H 'clientid: e5cd7e4891bf95d1d19206ce24a7b32e' \

  -d '{
```

## 9. 最佳实践与注意事项

### 9.1 模块要不要独立？

**推荐独立成 `ruoyi-modules/ruoyi-xxx`**，而不是把代码塞进 `ruoyi-system`。原因：

- 业务模块独立，方便以后单独拆微服务。
- 不影响系统核心模块的编译速度。
- 代码边界清晰，便于权限和菜单管理。

### 9.2 权限标识约定

统一使用 `模块:功能:动作` 三段式：

```
invoice:info:list
invoice:info:add
invoice:info:edit
invoice:info:remove
invoice:info:export
invoice:info:query
```

后端 `@SaCheckPermission`、前端 `v-hasPermi`、数据库 `sys_menu.perms` 必须完全一致。

### 9.3 前端组件路径

数据库里 `component = 'invoice/info/index'` 必须真实对应文件：

```
plus-ui/src/views/invoice/info/index.vue
```

否则登录后点菜单会报 `404` 或白屏。

### 9.4 字典使用

前端用 `useDict('invoice_type', 'invoice_status')` 拉字典，表格里用 `<dict-tag>` 显示；后端 Bo/Vo 里用 `String` 存字典值即可。这样既国际化友好，也方便以后改文案。

### 9.5 关于工作流

目前这个发票模块只是一个普通 CRUD。如果要接入「提交 → 审批 → 认证/驳回」的流程，后续可以：

1. 在 `ruoyi-invoice` 里新增一个「发票提交」接口，把状态改为 `submitted`。
2. 调用 Warm-Flow 创建工作流实例，把 `businessKey` 设为发票 ID。
3. 审批通过后回调修改状态为 `approved`，驳回改为 `rejected`。

具体做法可参考 `ruoyi-modules/ruoyi-workflow` 里的 `TestLeave` 示例。

### 9.6 代码生成器能不能替代手写？

RuoYi-Vue-Plus 自带代码生成器（系统管理 → 代码生成），可以：

1. 导入表结构。
2. 编辑字段信息（字段类型、查询方式、显示方式）。
3. 预览前后端代码。
4. 生成 zip 后复制到项目里。

对于标准 CRUD，用代码生成器更快；本次手写是为了把每一层都讲清楚。实际工作中，表设计好后可以先用生成器生成，再按需改 Service 业务和前端样式。
