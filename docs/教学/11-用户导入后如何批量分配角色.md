# 11-用户导入后如何批量分配角色

## 1. 导入后默认是什么角色？

**默认没有任何角色。**

RuoYi 自带的用户导入逻辑只往 `sys_user` 表里写用户基本信息，不会往 `sys_user_role` 表里写记录。

所以导入成功后：

- 用户能登录（密码是系统初始密码）。
- 但登录后左侧菜单是空的，因为没有任何角色 = 没有任何菜单权限。

---

## 2. RuoYi 自带 UI 能不能批量分配角色？

目前**不能直接批量分配角色**。

在「系统管理 → 用户管理」里：

- ✅ 支持批量删除。
- ❌ 不支持批量分配角色。
- 只能点每一行后面的「分配角色」按钮，一个一个设置。

如果导入 100 人，这样点确实 unacceptable。

---

## 3. 推荐方案：导入后用一条 SQL 批量分配默认角色

这是目前**最省事、不改代码**的方案。

### 3.1 思路

导入完成后，执行一条 SQL：

```sql
-- 把租户 721855 里所有没有角色的用户，都分配到「普通用户」角色
INSERT INTO sys_user_role (user_id, role_id)
SELECT u.user_id, '2080534408574390273'
FROM sys_user u
LEFT JOIN sys_user_role ur ON u.user_id = ur.user_id
WHERE u.tenant_id = '721855'
  AND ur.user_id IS NULL;
```

### 3.2 参数说明

| 参数 | 怎么获取 |
|---|---|
| `tenant_id = '721855'` | 在「租户管理」里看「租户编号」 |
| `role_id = '2080534408574390273'` | 在「角色管理」里看「角色编号」 |

### 3.3 执行方式

```bash
docker exec -i mysql mysql -uroot -proot -D ry-vue <<'EOF'
INSERT INTO sys_user_role (user_id, role_id)
SELECT u.user_id, '2080534408574390273'
FROM sys_user u
LEFT JOIN sys_user_role ur ON u.user_id = ur.user_id
WHERE u.tenant_id = '721855'
  AND ur.user_id IS NULL;
EOF
```

执行后，所有这次导入的「无角色用户」都会自动变成「普通用户」角色。

### 3.4 优点和局限

- ✅ 不用改代码。
- ✅ 一次导入、一条 SQL，几秒钟搞定。
- ❌ 只能分配一个默认角色，不能按人分配不同角色。
- ❌ 每次导入后都要执行一次。

---

## 4. 进阶方案：Excel 里加一列「角色编号」

如果你希望导入时就能指定每个人的角色，需要改代码。

### 4.1 需要改哪些地方

1. **后端导入 VO**：`SysUserImportVo.java`
   - 新增字段：`private Long roleId;`
   - 加 `@ExcelProperty(value = "角色编号")`。

2. **后端导入监听器**：`SysUserImportListener.java`
   - 在 `insertUser` 之前，把 `roleId` 设置到 `SysUserBo` 的 `roleIds` 数组里。

3. **前端导入模板**：下载模板时显示「角色编号」列。

### 4.2 改完后的 Excel 示例

| 用户账号 | 用户昵称 | 部门编号 | 用户性别 | 账号状态 | 角色编号 |
|---|---|---|---|---|---|
| zhangsan | 张三 | 2080532456532725762 | 男 | 正常 | 2080534408574390273 |
| lisi | 李四 | 2080532456532725762 | 女 | 正常 | 2080534408574390273 |
| manager1 | 王经理 | 2080532456532725762 | 男 | 正常 | 2080534408574390274 |

这样不同人可以导入不同角色。

## 5. 另一个方案：导入时自动分配默认角色

如果你不想每次导完都执行 SQL，也不想 Excel 里写角色编号，可以改代码让导入自动带一个默认角色。

### 5.1 改哪里

在 `SysUserImportListener.java` 的 `invoke` 方法里：

```java
SysUserBo user = BeanUtil.toBean(userVo, SysUserBo.class);
user.setRoleIds(new Long[]{ 2080534408574390273L });  // 默认普通用户角色
ValidatorUtils.validate(user);
user.setPassword(password);
user.setCreateBy(operUserId);
userService.insertUser(user);
```

### 5.2 更优雅的做法

不要写死角色 ID，而是从系统参数读取：

```java
String defaultRoleId = SpringUtils.getBean(ISysConfigService.class)
    .selectConfigByKey("sys.user.defaultRoleId");
user.setRoleIds(new Long[]{ Long.valueOf(defaultRoleId) });
```

然后在「参数管理」里加一个参数 `sys.user.defaultRoleId`，值为默认角色 ID。

这样以后想改默认角色，改参数就行，不用重新打包。

---

## 6. 三种方案对比

| 方案 | 改代码吗？ | 灵活度 | 适用场景 |
|---|---|---|---|
| **导入后执行 SQL** | 否 | 低，只能统一默认角色 | 临时批量导入、MVP |
| **Excel 加角色编号列** | 是 | 高，每人可不同 | 正式使用、HR 批量入职 |
| **导入自动分配默认角色** | 是 | 中，统一默认角色 | 正式使用、简化操作 |

---

## 7. 推荐落地路径

### 阶段 1：现在先用 SQL（不改代码）

每次批量导入用户后，执行：

```sql
INSERT INTO sys_user_role (user_id, role_id)
SELECT u.user_id, '你的默认角色ID'
FROM sys_user u
LEFT JOIN sys_user_role ur ON u.user_id = ur.user_id
WHERE u.tenant_id = '你的租户ID'
  AND ur.user_id IS NULL;
```

### 阶段 2：稳定后改成自动分配默认角色

修改 `SysUserImportListener.java`，从系统参数读取默认角色 ID。

这样 HR 只需要上传 Excel，不需要再找人执行 SQL。
