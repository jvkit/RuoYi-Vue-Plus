# 采购流程简化设计（v0.2，基于真实模板）

> 状态：设计稿，未实现。供产品负责人评审。
> 依据：对比 Python 版 + 6x 版，并分析真实模板 `采购素材/` 下两份采购申请单 Excel。

## 一、真模板分析（采购素材）

两份真实模板结构高度一致（同一机构"采购申请单"格式），各有 **3 个 sheet**：

**Sheet1 `Tabelle1`（主表）列**（10.活细胞 有 16 列；8.0105淘宝件 略去"单价/开票实付金额"为 14 列）：

| 列 | 表头 | 类型 |
|---|---|---|
| A | 序号 | 自动 |
| B | 采购种类 | 科研类 / 非科研类 |
| C | 一级分类 | 100材料 / 600其他 / 700危险化学品 / 800设备 / 900费用 |
| D | 二级分类 | 101金属材料 / 102高分子材料 …（字典） |
| E | 项目归属 | 医用应用物理研发测试平台 / 各科学家工作室 / 非项目经费 |
| F | 品名 | 必填 |
| G | 单位 | g / 套 / 台… |
| H | 数量 | 必填 |
| I | 规格型号/技术要求 | 4N粉末、M2M3… |
| J | 参考品牌 | 中科言诺… |
| K | 单价 | （10.活细胞有；8.0105 无单独单价列，只写总价） |
| L | 预估总价 | （10.活细胞）；8.0105 的 K 是总价 |
| M | 开票实付金额 | 仅 10.活细胞 |
| N | 保管人 / 使用人 / 采购理由 | 10.活细胞 N/O/P；8.0105 L/M/N |
| O | （8.0105 无表头列）**用户粘贴的商品标题/描述** | 如 `...-tm` 结尾 = 淘宝 |

**Sheet2 `二级分类目录`（字典）**：`采购种类 → 一级分类 → 二级分类` 三级联动下拉数据（科研类/100材料/101金属材料…）。

**Sheet3 `项目归属`（字典）**：`医用应用物理研发测试平台 / 杨旭三科学家工作室 / 彭蠡科学家工作室 / 谢浩科学家工作室 / 天目湖医用应用物理研究中心 / 非项目经费`。

### 关键发现（支撑"少填"）
1. **用户实际就填**：品名、数量、规格、品牌、（单价）、项目归属、粘贴商品链接/标题；其余（序号、预估总价、开票实付金额）多是计算或重复。
2. **O 列 = 商品粘贴区**：淘宝件用户直接贴商品标题/链接（`-tm`=淘宝）。→ 这就是"贴链接/标题 → 识别平台 → 匹配供应商"的天然入口。
3. **项目归属 = 我们的二级项目/工作室**。
4. **一级/二级分类**：三级字典，选二级时一级/采购种类可自动带出，减少手填。

## 二、设计目标与原则

- 核心：填少量信息 → 生成多 sheet 的"采购申请单"Excel（对齐真模板）。
- 只填必要的：最少 `品名 / 数量 / 单价 / 项目归属`；规格/品牌可选；**贴商品链接/标题**可自动补平台、供应商。
- 能自动就自动：序号、预估总价、采购种类、一级分类、保管人/使用人默认当前人。
- 合并两套订单（6x 的申请+订单）为一套；供应商落到明细级。

## 三、模板设计（多 sheet，对齐真模板）

**Sheet1 `采购申请单`（主表）列** —— 目标"少填"：

| 列 | 表头 | 填法 |
|---|---|---|
| A | 序号 | **自动** |
| B | 采购种类 | **默认"科研类"**（可改） |
| C | 一级分类 | **自动带出**（选二级后） |
| D | 二级分类 | 下拉（Sheet2 字典） |
| E | 项目归属 | **下拉（Sheet3 字典 / 二级项目）** |
| F | 品名 | **必填** |
| G | 单位 | 可选（默认"个/台"） |
| H | 数量 | **必填** |
| I | 规格型号/技术要求 | 可选 |
| J | 参考品牌 | 可选（贴商品时自动带） |
| K | 单价 | **必填** |
| L | 预估总价 | **自动** = 单价×数量 |
| M | 开票实付金额 | 可选/后置 |
| N | 保管人 / 使用人 | **默认当前登录人** |
| O | 采购理由 | 可选/默认 |
| P | 商品链接 / 平台 / 供应商 | 附加列（贴链接识别，可不显示在正式表） |

**Sheet2 `二级分类目录`（字典）**：`采购种类 / 一级分类 / 二级分类` 三级（照抄真模板）。
**Sheet3 `项目归属`（字典）**：工作室/平台列表（照抄真模板 + 系统项目）。

> 模板 = 真模板 + 我们加的"链接/平台/供应商"附加能力。正式导出时 Sheet1 可按需隐藏附加列，保持与真模板一致外观。

## 四、"少填"映射（真模板列 → 处理）

| 真模板列 | 处理 | 理由 |
|---|---|---|
| 序号 | 自动 | 纯递增 |
| 采购种类 | 默认科研类 | 用户基本固定 |
| 一级分类 | 自动带出 | 由二级分类推导 |
| 二级分类 | 下拉字典 | 三级字典，选即可 |
| 项目归属 | 下拉 | = 二级项目，可选默认 |
| 品名 | 必填 | 核心 |
| 单位 | 可选默认 | 多数可给默认 |
| 数量 | 必填 | 核心 |
| 规格型号 | 可选 | 看情况 |
| 参考品牌 | 可选/自动 | 贴商品可带出 |
| 单价 | 必填 | 需用户填（链接不含价） |
| 预估总价 | 自动 | = 单价×数量 |
| 开票实付金额 | 可选/自动 | 可=预估 |
| 保管人/使用人 | 默认当前人 | 申请人即保管/使用 |
| 采购理由 | 可选/默认 | 可给模板默认句 |

## 五、链接/标题 → 平台 → 供应商

- 用户在明细"商品链接/标题"列贴淘宝/京东链接或商品标题。
- **平台识别**（域名正则）：
  - `taobao.com` → 淘宝；`tmall.com` → 天猫；`jd.com` → 京东；`pinduoduo.com/yangkeduo.com` → 拼多多；`1688.com` → 1688；`douyin.com` → 抖音；其它 → 其他。
  - 若只贴商品标题（无链接，如 `-tm`），按结尾 `-tm/-jd` 等或关键词兜底判断平台。
- **供应商匹配**（非必填，识别了就帮填）：
  1. 精确：供应商 `link` 与商品链接同域名 → 自动填。
  2. 建议：同平台多供应商 → 下拉点选。

## 六、后端数据模型（对齐模板）

- **主表 `pms_purchase`**（合并申请+订单）：`purchase_no(自动) / project_id(二级) / title(自动) / amount(自动) / status(草稿→已下单→收货) / purchase_type / order_date / delivery_date / apply_reason / remark`。
- **明细 `pms_purchase_item`**：`item_name(必填) / quantity(必填) / unit_price(必填) / spec / brand / unit / link(新增) / platform(新增,自动) / supplier_id(明细级,新增) / amount(自动) / actual_price / order_status / tracking_no / category_1(一级分类,自动) / category_2(二级分类,下拉) / custodian(保管人,默认) / user(使用人,默认) / apply_reason(采购理由)`。
- **供应商 `pms_supplier`**：加 `platform / link / rating`；去掉 `supplier_code` 必填。
- **分类字典**：`pms_category`（采购种类/一级/二级，来自 Sheet2）。
- **项目归属**：= 系统二级项目（来自 Sheet3 + 项目）。
