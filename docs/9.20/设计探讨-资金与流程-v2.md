### 1.2 备用金语义（v2 澄清）

- **每个员工都有备用金额度（一万）**，向财务申请下来后钱给到采购部门使用。
- 每人额度固定一万、还款也是一万 → **「是谁的钱」大概率可以不记录**（额度统一，还钱时按人还一万即可）。
- 可能的实现选项（待部门确认，见 4.1）：
  - a. 采购申请（自购）多弹一个词条（备用金来源/用途）
  - b. 流程规范约束：花谁的钱谁提交（不写代码，靠规范）
  - c. 干脆不记录是谁的钱（当前倾向）
- 用户原话："其实也倒是不需要记录是谁的钱，因为我们申请的是一万，到时候还钱的时候也是一万"。

### 1.3 回款 / 钱款状态（用户不懂，我给的可能解释，后续继续聊）

资金类系统常见的几种「钱的状态」，供后续讨论：

| 概念 | 含义 | 在我们场景的可能形态 |
|---|---|---|
| 拨入（in 流水） | 钱进来 | 员工申请一万备用金获批 → 财务拨付，记一条 in |
| 核销 | 用票据冲销借款 | 采购完成拿发票/验收单冲销备用金，借一台记录一笔 |
| 余额 | 备用金剩余 | 拨入 - 已核销 = 剩余额度 |
| 回款 | 垫付的钱回来 | 对公采购后项目方/财务把钱打回来，记 in |
| 归还 | 还清借款 | 备用金到期/项目结束，剩余额度退回 |

**目前系统**：`pms_fund_flow.flow_type` 已建模 `in`（流入）但全链路无写入——「拨入/回款」将来落库大概率就是启用它。这部分不急，等资金管理主体验落地后再聊。

## 二、流程跳过最高决策人 —— 实现选项（需你拍板）

> 前置纠错：之前我提的 `autoPass` **不适用**——它只自动跳过「当前审批人本人是办理人」的后续节点，李迪的节点王建龙审完不会触发。以下为修正后的三个方案。

### 方案 A：改网关出边指向（零代码，推荐 ✅）

现状：`gateway_amount` 出边 `ge@@amount|1000 → supreme_decision_maker`。
做法：一条幂等 SQL 把该出边 `next_node_code` 临时改为 `end`（或直接把两条出边都指向 end）。

- 优点：**零代码**；一条 UPDATE 即可跳过；恢复也是一条 UPDATE（改回 `supreme_decision_maker`）；节点和角色都保留在流程定义里。
- 缺点：跳过期间最高决策人**完全无痕迹**（审批记录里没有这一环，也没有"已跳过"字样）。
- 风险：极低。流程图上 supreme 节点会变成"孤立节点"（不可达），图上仍显示但流程不走它——正好提醒后续要加回来。

### 方案 B：节点自动通过监听器（少量代码，有痕迹）

做法：给 supreme 节点配 `listener_type/listener_path`，写一个小的节点创建监听器，任务创建时自动 `taskService.skip()`（历史里留"流程引擎自动审批"记录）。

- 优点：**有痕迹**——审批记录能看到这一环被自动通过；语义清晰。
- 缺点：要写代码（项目内目前无节点级 Listener 先例，但有 GlobalListener 参考）；恢复 = 删节点上的监听配置。
- 风险：中低。自动跳过逻辑如果处理不好可能死循环/误伤，需要仔细写（只对 supreme 节点生效）。

### 方案 C：CEO 审批时"直达结束"（前端+参数，中代码）

做法：CEO 办理时前端传 `nodeCode=end` 走 `passAtWill`，跳过 supreme。

- 优点：灵活（CEO 可以选择是否跳过）；有审批记录。
- 缺点：改动面最大（前端审批按钮+后端参数）；且"是否跳过"变成 CEO 的主观决定，不是规则。
- 风险：中。不符合"初期从简、规则化跳过"的诉求。

**我的推荐：方案 A**。从简阶段就该零代码；痕迹问题在"李老师现阶段完全不打扰"的前提下无所谓——反正没人审批，留白比留"自动审批"记录更真实；恢复时一条 SQL。

## 三、资金管理改造理解（迭代后）

### 3.1 记录详尽原则 ✅

- 流水每条已记录：project_id/name、request_id/code/title、amount、operator——**已经够详尽**。
- 缺的维度：`title_type`（自购/对公）——从申请单带过来即可（`pms_procurement_request.title_type` 已存在）。
- 「是谁的钱」：v2 澄清后倾向**不记录**（额度统一一万），待部门确认。

### 3.2 展示改造

- 资金面板加「备用金 / 项目」筛选：
  - **项目** = 对公，正常按项目展示（现状逻辑）
  - **备用金** = 自购，流水按备用金维度展示（第一期可以先不搞池子余额，只筛流水）
- 筛选放流水列表筛选栏（现状已有：项目下拉/关键字/日期范围，加一个即可）。

### 3.3 第一批实施范围（建议）

1. `pms_fund_flow` 加 `title_type` 列（幂等 SQL，带默认值）+ 写流水时从申请单带入
2. 前端资金面板流水筛选加「备用金/项目」（实质是按 title_type + 是否关联项目筛）
3. 顶部卡片/项目资金视图维持现状不动
4. 报销相关一律不碰
