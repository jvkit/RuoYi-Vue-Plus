### 1.3 现状缺口（开发前必知）

1. 资金管理是**只读面板 + 自动流水**：Controller 只有 list/getInfo/summary/export/sync，无新增/编辑/删除。
2. 「自购/对公」只在采购申请上（`pms_procurement_request.title_type`，varchar，`procurement_6x_increment.sql:19` 加列），**流水不带此维度** → 资金面板无法按自购/对公拆分。
3. 「回款」「备用金」「是否收到报价」**全局零命中**，完全没建模。只有 `quotation_url`（对公报价单附件）和 `pms_purchase_contract.quotation_url`。
4. `/procurement/fund/sync` 用 `procurement:fund:edit` 权限，但该权限**无菜单定义**（SQL 只插了 1801140/41/42），实际只有超管能调。
5. 报销单不产生资金流水，报销与资金是两套独立表。

### 1.4 前端

- 页面 `plus-ui-6x/src/views/procurement/fund/index.vue`：顶部 4 卡片（总预算/已用/剩余/本月流出）+ 项目资金视图 + 流水明细（筛选：项目下拉/关键字/发生日期范围）。
- API `src/api/procurement/fund/index.ts`（listFundFlow / getFundSummary / exportFundFlow）；**前端没接 `/sync` 接口**。
- 报销页 `src/views/procurement/reimbursement/index.vue` + api。
- 菜单：1801140 资金管理（C，`procurement/fund/index`，perms `procurement:fund:list`）+ 1801141 查询 + 1801142 导出；父 1801000 采购管理，图标 `money`。
- 角色绑定：common_user 只给 1801140+:query 不给 :export（`procurement_6x_common_user_perms.sql:63-80`）；**v5 已从 common_user 移除 1801140/41/42**（`procurement_6x_v5_roles_and_menus.sql:42-43`）；`procurement_fund.sql:82-84` 给角色补权限的语句是注释掉的，未生效。

## 三、采购申请流程现状（pms_request）

### 3.1 当前生效的流程结构（v5，definition_id=900000000000000001，已查库核实）

```
start(0) → apply(1,${initiator}) → leader(1,${leaderId}) → ceo(1,role:…009)
  → gateway_amount(3 排他网关)
      ├─ lt@@amount|1000 → end(2)
      └─ ge@@amount|1000 → supreme_decision_maker(1,role:…010) → end(2)
退回线 REJECT：leader/ceo/supreme_decision_maker → start
```

- SQL：`procurement_6x_v5_flow.sql:22-84`（节点/跳转）；v6 脚本仅修坐标。
- 所有节点 any_node_skip=NULL、listener_type=NULL、form_path='/procurement/request/detail'。
- `amount` 变量由提交时 `PmsProcurementRequestServiceImpl.submitAndStartFlow`（:287-290）传入。
- 条件格式 `<比较符>@@<变量>|<字面值>`，仅网关（node_type=3/4/5）出边判条件，普通节点出边只取第一条 PASS。

### 3.3 Warm-Flow 1.8.5 跳过/自动通过能力（jar 反编译核实）

**引擎 API**（`~/.m2/repository/org/dromara/warm/warm-flow-core/1.8.5/`）：
- `TaskService.skip(taskId, FlowParams)` / skipByInsId / pass / reject / **passAtWill / rejectAtWill**（任意跳转指定目标节点）/ taskBack / rejectLast / revoke / termination / transfer / depute / addSignature / pending
- `FlowParams` 可设：nodeCode、skipType、permissionFlag、variable、**ignore（忽略办理权限校验）**、hisStatus、nextHandler
- `Node.getAnyNodeSkip()`：任意跳转开关（当前全 NULL）

**6x 封装层现成机制（最相关）**：
1. **`autoPass` 全局自动审批**：`FlowConstant.AUTO_PASS="autoPass"`（FlowConstant.java:89）。启动时 `StartPrepareInstanceComponent.java:38-42` 从 `flow_definition.ext` JSON 解析 `{"autoPass":true}` 放入实例变量；办理走 LiteFlow 分支 `completeNeedAutoPass` → `CompleteAutoPassComponent`：**递归扫描后续 waiting 任务，当前登录人仍是办理人的自动 skip**（消息"流程引擎自动审批！"）。
2. **`ignore` 忽略权限**：`FlowConstant.VAR_IGNORE="ignore"`，`CompleteExecuteComponent.java:40` 传 `FlowParams.ignore(true)`；`WorkflowServiceImpl.completeTask(Long,String)` 有现成用法（后台无用户上下文审批）。
3. **动态指定办理人**：`WorkflowGlobalListener.assignment`（:118-132）消费流程变量 `PASS:<nodeCode>` / `BACK:<nodeCode>`（值冒号分隔用户 ID），覆盖任务 permissionList。
4. 条件跳过必须走网关出边，普通节点配条件无效。

## 四、报销模块现状（2026-09-20 补充探索，重要）

**结论：报销是半成品，功能等于没实现，需从零补完。**

### 4.1 后端

- 全套类已存在：`domain/PmsReimbursement.java` + bo/vo + `mapper/PmsReimbursementMapper.java`（无 XML，全走 MP 通用方法）+ `service/IPmsReimbursementService.java` / `impl/PmsReimbursementServiceImpl.java` + `controller/PmsReimbursementController.java`（`/procurement/reimbursement`）。
- Controller 实际接口：`GET /list`、`POST /export`（导出列表 Excel）、`GET /{id}`、`POST`（add）、`PUT`（edit）、`DELETE /{ids}`。
  - **没有 `/download/{id}`** —— 前端下载按钮调的就是它 → 必然 404。
  - add/edit/remove 用了 `procurement:reimbursement:edit` / `:remove` 权限，**无对应菜单定义**（SQL 只插了 1801130 list / 1801131 query / 1801132 add / 1801133 export）。
- `PmsReimbursementServiceImpl` 只有 CRUD + `generateReimbursementCode()`（`reim-yyyyMMdd-NNN`，按当天前缀计数 +1）。
  - **无任何打包逻辑**：全仓 grep `ZipOutputStream` / `setFileUrl` 零命中 → `file_url` 永远为空。
  - `buildQueryWrapper` 支持按 code/requestId/acceptanceId/projectId/applicant/status/创建时间区间过滤。

### 4.2 前端

`plus-ui-6x/src/views/procurement/reimbursement/index.vue`（300 行）：
- 列表列：报销编号 / 关联申请(requestCode) / 项目 / 申请人 / 状态(dict-tag statusOptions) / 打包文件（`fileUrl` 有值才显示"查看"，否则 `-`）
- 「生成报销包」= `handlePack()` 打开弹窗 → 选一张申请（`onRequestChange` 带出 projectId/projectName/applicant=leader/acceptanceId）→ `submitPack()` 只调 `addReimbursement({..., status:'packing'})` 插一条记录，**不产生文件**。
- 「下载」= `handleDownload()` 调 `proxy.download('procurement/reimbursement/download/' + id)` → 后端无此接口。
- API：`src/api/procurement/reimbursement/index.ts`（无 pack/download 专用方法）。

### 4.3 表结构缺口

`pms_reimbursement`（`procurement_6x_v2_tables.sql:296`）现有字段见 §1.2，**缺**：
- `amount` / `paid_amount` / `paid_date` / `paid_by`（汇款相关，全无）
