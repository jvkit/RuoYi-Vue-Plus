## 一、导出 Excel A1 颜色修复

**现象**：导出采购申请单，第一行「项目归属」文字在 WPS 里显示为红色。

**原因**：`最终模板.xlsx` 的 A1 单元格字体用的是主题色 `theme=1`，Excel 里主题是黑色没问题，但 WPS 对该主题色的解析会渲染成红色。

**修复**：`PmsProcurementRequestServiceImpl#exportFormExcel` 中写完 A1 值后，强制重建该单元格字体为固定黑色 RGB（`FF000000`），不再依赖模板主题色。已用 curl 下载导出文件验证 A1 字体为黑色。

## 二、明细级「采购原因」字段

**需求**：Excel 每行商品有各自的采购原因（Q 列），此前只有申请级一个 `applyReason`，无法区分到商品行。

**改动**：
- SQL：`script/sql/procurement_6x_v7_purchase_reason.sql`（幂等）——`pms_procurement_request_item` 加列 `purchase_reason varchar(500)`
- 后端：`PmsProcurementRequestItem` 实体 / `Bo` / `Vo` 加字段；导出逻辑 Q 列**优先取明细级 `purchase_reason`，为空回退申请级 `applyReason`**
- 前端：`src/views/procurement/request/` 表单明细行加「采购原因」输入框

**顺带说明（模板位置问题）**：导出模板在**代码文件夹**而非数据库——`ruoyi-modules/ruoyi-procurement/src/main/resources/templates/`，当前实际使用的是 `最终模板.xlsx`（旧 `采购申请单模板.xlsx` 已弃用但保留在目录）。sheet3 等纯模板内容改动直接改 xlsx 文件即可，不涉及代码与数据库。

## 三、common_user 补 OSS 查询权限

**现象**：彭赛威（普通用户）验收上传 3 个发票 PDF，AI 识别已返回结果，但流程中断、文件回显失败。

**原因**：验收上传文件后前端调 `GET /resource/oss/listByIds/{id}` 回显，需要 `system:oss:query`；此前 common_user 只绑了 OSS 上传/下载按钮权限，查询权限缺失，返回 403 中断后续保存。

**修复**：`script/sql/procurement_6x_v8_common_user_oss_query.sql`（幂等）——给 `common_user` 及 `procurement_contact` / `purchase_staff` / `procurement_applicant` 补绑菜单 `1761400000000001600`（system:oss:query）。superadmin 走代码特判全量权限，无需处理。

## 四、全链路 Playwright 测试结论

测试脚本：`work_twst/app/ruoyi6x-server/scripts/`（`local-full-flow.mjs`、`mobile-check.mjs`）。

| 链路 | 结果 |
|---|---|
| 采购申请：提交 → 项目负责人审批 → CEO 审批（金额网关 <1000 走 finish 分支）→ finish | ✅ 通过 |
| 采购验收：验收提交 → 驳回 → 修改重提 → 审批通过 → finish → 采购申请 `acceptance_status=done` → 自动入库 | ✅ 通过 |
| 领用申请：提交 → 仓库管理员审批 → finish → 库存扣减 | ✅ 通过 |
| 手机端 `/mobile/acceptance` 打开、查看验收数据 | ✅ 无权限报错 |

**测试过程中的关键发现**：UI 里「审批 → 弹窗提交」按钮点击不稳定（日志报已通过但 `flow_task` 仍是 waiting），脚本内改用 API 直调更可靠：
- 通过：`POST /workflow/task/completeTask`，body `{taskId, messageType: ["1"], message}`
- 退回：`POST /workflow/task/backProcess`，body `{taskId, nodeCode, ...}`
- 我的待办路由：`/task/taskWaiting`

**AI 发票识别覆盖情况**：目前只有**电脑端**采购验收页有「AI 识别匹配发票」弹窗（多轮上传、匹配改名、报告）；**手机端** `/mobile/acceptance` 是纯手工填写+上传，**没有**接入 AI 识别。如需手机端也支持，后续单独做。
