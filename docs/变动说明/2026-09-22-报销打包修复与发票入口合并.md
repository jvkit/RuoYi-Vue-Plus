# 2026-09-22 报销包打包修复 + 发票入口合并

> 范围：本地开发环境（后端 8091 / 前端 8082）。仅本地改动，未部署、未构建 dist。

## 一、背景

用户确认的两条业务决策：

1. **发票与验收有时差** —— 验收时不该强制上传发票 PDF，发票应当独立成一个入口。
2. **报销导出 = 采购申请 Excel + 验收图片 + 发票 PDF**，打成 ZIP，解压后为：
   - 文件 1：`【自购】项目名_09月22日_名称.xlsx`
   - 文件夹 `验收图片/`：`序号_商品名_验收图.png`
   - 文件夹 `发票pdf/`：`序号_商品名_发票.pdf`
   - 另有 `清单.txt` 说明文件

## 二、本轮改动

### 1. 发票入口合并（干掉老发票模块）

老发票模块是 5.x 迁移过来的 Dify 玩具，真实场景（选中已验收订单 → 一键上传 / 手动挂载）已经在发票台账里实现了，故整体下线。

- 删除前端 `plus-ui-6x/src/views/invoice/`（info / employee / usage 三个页面）
- 删除前端 `plus-ui-6x/src/api/invoice/`
- SQL `ruoyi-6x/script/sql/procurement_6x_v17_invoice_merge.sql`：
  - `pms_invoice` 加 `amount` 列（不含税金额快照）
  - 新增按钮权限 `procurement:invoice:upload`（菜单 1801163）
  - 摘除老发票管理菜单 1804000~1804012（与台账共用 `invoice_info` 表，无数据迁移）
  - superadmin 角色补绑新按钮

### 2. 发票台账新增「上传发票」

`plus-ui-6x/src/views/procurement/invoice/index.vue` 新增上传弹窗，两个 Tab：

- **AI 一键匹配**：选关联申请 → 拖入多张 PDF → 复用 `/procurement/acceptance/ai-invoice-match` 端点，按商品名匹配、自动写台账；冲红标记「冲红」，对不上订单的记为无效发票。支持多轮补充（每轮识别后队列自动清空）。
- **手动挂载**：先选一条验收明细，再选 PDF，直接登记台账并关联商品。

后端新增 `manualUpload` + `POST /procurement/invoice/manual-upload`。

### 3. 验收页摘掉发票列

`plus-ui-6x/src/views/procurement/acceptance/index.vue` 移除「发票附件」上传列与必填校验，保留 AI 识别按钮。**后端接口未动**（发票字段仍在表里，兼容历史数据）。

### 4. 报销包打包/下载修复（核心 bug）

文件：`ruoyi-6x/ruoyi-modules/ruoyi-procurement/.../service/impl/PmsReimbursementPackService.java`

| # | 问题 | 修复 |
|---|---|---|
| 1 | `file_url` 存的是 OSS **URL**，下载接口按 ossId 解析 → 500「无法解析附件 ossId」 | 改存 ossId：`reimb.setFileUrl(String.valueOf(oss.getOssId()))` |
| 2 | `resolveOssId` 用正则从 URL 抠数字，但 MinIO 文件名是 UUID（`ae5de9e1....png`）→ 抠不出 | 注入 `SysOssMapper`，按 `SysOss::getUrl` eq 反查取 ossId |
| 3 | 附件后缀解析成 `.bin` | `resolveSuffix` 优先取 `sysOssService.getById(ossId).getFileSuffix()` |
| 4 | Hutool `ZipUtil.zip` 把目录压平 + 中文文件名乱码 | 新增 `zipDir(Path, File)`：`java.util.zip.ZipOutputStream` + `StandardCharsets.UTF_8` + `Files.walk` 递归，`dir.relativize` 保留 `验收图片/`、`发票pdf/` 结构 |

SQL 前置：`procurement_6x_v18_reimbursement_status.sql` 把 `pms_reimbursement.status` 由 `varchar(20)` 扩到 `varchar(32)`，默认 `packing`（此前 `packed` 超长报 `Data too long for column 'status'`）。
