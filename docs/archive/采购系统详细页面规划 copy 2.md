# 采购系统详细页面规划（v2 · 已按批注修订）

> 本文档已吸收原文档中的全部讨论批注：权限体系、审批模式、对接人来源、资金校验、BOM 层级、发票 PDF、自动入库、在途数量、验收逻辑等均已落定。
> 一阶段=纯传统（无AI/邮件/扒价/泛微）；二阶段=AI+外部对接。

## 〇、权限体系设计（先看这个）

- **能力 = 权限点**：所有功能拆成权限点（如"项目管理-新增""采购申请-审批""仓库-出入库""BOM-编辑"），权限点分配给角色，角色赋予具体账号。**验收用的就是采购同一套权限体系**，不单独建"验收角色"。
- **项目负责人**：被选为项目负责人的用户，**自动获得该项目采购申请的审批权**（数据权限=我负责的项目），无需另行配角色。换负责人即自动换审批人。
- **对接人**：由 **admin 在部门/组织架构中配置**（不是提交者选择），配置在"部门管理"里，走单批/群批规则（见下）。
- **审批节点到自己自动跳过**：Warm-Flow 支持，若流程节点执行人恰好是提交者本人，自动跳过往后走。

### 审批的两种模式
| 模式 | 含义 | 例子 |
|---|---|---|
| **单批** | 审批对应到**具体某个人**（如上级），这个人批了就过 | 需要上级批的 |
| **群批** | 审批对应到**部门/群体**，群体内**任意一人**批了就过 | 采购审批由一个部门负责 |

配置都在**部门管理/组织架构**里定义（RuoYi 原生有部门、岗位，可配置上级关系；群批可落在部门级审批人上，由我们自己扩展）。

## 角色定义

| 角色 | 来源 | 说明 |
|---|---|---|
| 采购申请人 | 当前登录用户（系统自动记录） | 提交申请的人，不单独分配 |
| 项目负责人 | `pms_project.leader`，选项目后自动带出 | 审批所属项目的申请；被选即自动获得该项目审批权 |
| 采购对接人 | **admin 在部门/组织架构中配置**，提交者不选 | 审批 + 转订单 + 合同 + 验收 |
| 仓库看管人 | 独立角色 | 入库/出库/领用审批 |
| 系统管理员 | admin | 项目管理/分类/菜单/角色/对接人配置 |

**审核方式**：提交后进入审批，审批人 = 项目负责人 + 采购对接人（均来自项目配置与组织架构，不是提交者选）。单批/群批按配置；节点到自己自动跳过。

## 页面一：项目管理

### 1.1 用途
管理多级项目树（长三角→项目→子项；天目湖→显微镜系统→电路部分/光学部分…），管理项目预算与资金消耗。

### 1.2 数据库表
`pms_project`（已有，需改造加列）

### 1.3 字段表

| 字段 | 数据库列 | 类型 | 来源 | 说明 |
|---|---|---|---|---|
| 项目ID | `id` | bigint | 系统生成 | 主键 |
| 上级项目 | `parent_id` | bigint | 用户选 | 0=顶级（区域），非0=子项目；支持无限层级 |
| 项目编码 | `project_code` | varchar(64) | **自动生成** | 格式 `purp-YYYYMMDD-NNN`，表单不显示，提交时后端生成 |
| 项目名称 | `project_name` | varchar(200) | **用户填** | 如"SIM显微镜系统-电路部分" |
| 项目负责人 | `leader` | varchar(64) | **用户选** | 关联 `sys_user`，下拉选真实用户；**被选即自动获得该项目审批权** |
| 项目预算 | `budget` | decimal(12,2) | **用户填** | 该项目可用的资金额度 |
| 已用金额 | `used_amount` | decimal(12,2) | **系统自动** | 采购申请通过后累加，初始0；只读不可编辑 |
| 剩余资金 | — | — | **系统计算** | `budget - used_amount`，前端实时算，不入库 |
| 开始日期 | `start_date` | date | **用户填（可空）** | 非必填，有些项目周期不确定 |
| 结束日期 | `end_date` | date | **用户填（可空）** | 非必填 |
| 状态 | `status` | tinyint | **用户选** | 0=停用 1=正常，默认1 |
| 备注 | `remark` | varchar(500) | **用户填（可空）** | |
| 创建时间 | `create_time` | datetime | **系统自动** | BaseEntity 自带 |
| 创建人 | `create_by` | bigint | **系统自动** | BaseEntity 自带，当前登录用户 |
| 删除标志 | `del_flag` | bigint | **系统自动** | 逻辑删除 |

### 1.4 业务规则
- **多级树**：区域（长三角/天目湖/北京）= 顶级节点（`parent_id=0`），下面挂项目，项目下挂子项，不限层级。
- **资金约束**：子项目预算 ≤ 父项目剩余预算（父预算 - 父已用 - 其他子项目预算之和）。
- **采购约束**：采购申请总金额 ≤ 所选项目的剩余资金，**超了直接拒绝申请**（不是拦截提示）。
- **资金消耗归属**：通过 `pms_procurement_request.project_id` 关联项目，申请通过后 `used_amount` 累加，可按项目维度查看资金消耗明细。
- **负责人权限联动**：被选为项目负责人的用户自动获得该项目申请的审批权（数据权限=我负责的项目），换人即换审批人。

### 1.5 权限
| 操作 | 角色 |
|---|---|
| 新增/编辑/删除项目 | 仅系统管理员 |
| 查看项目树 | **仅管理员**（普通用户无此界面） |

> **普通用户看不到项目管理界面**。填表时通过项目选择器只拿到项目名，看不到预算/负责人等其它信息。

### 1.6 页面交互
- 树形表格展示（区域→项目→子项，支持展开/折叠）
- 顶级节点用颜色或图标区分（区域 vs 项目 vs 子项——用层级着色）
- 新增：选上级项目（可空=建区域）→ 填名称/负责人/预算/日期
- 资金列实时显示 剩余 = 预算 - 已用，剩余不足时标红

## 页面二：采购申请

### 2.1 用途
采购申请人提交采购申请，包含明细物料清单；自购/对公两种模式表单不同；提交后进入审批流。

### 2.2 数据库表
- 主表：`pms_procurement_request`（已有，需改造加列）
- 明细表：`pms_procurement_request_item`（已有，字段已够，无需改）

### 2.3 主表字段表（采购申请单）

### 2.5 自购 vs 对公表单差异

| 差异点 | 自购 | 对公 |
|---|---|---|
| 付款截图 | **必填**（淘宝/京东/美团付款截图） | 不显示 |
| 报价单 | 不显示 | **必填** |
| 开票信息 | 不显示 | **必填**（抬头/税号/地址电话/开户行账号） |
| 其余字段 | 相同 | 相同 |

前端用 `v-if="titleType === '自购'"` / `v-if="titleType === '对公'"` 控制显隐。

### 2.6 业务规则
- **申请人** = 当前登录用户，后端 `LoginHelper.getUserId()` 自动写入 `create_by`，前端表单不显示此字段。
- **项目负责人** = 选项目后从 `pms_project.leader` 自动带出，**系统背后做**（前端默认不显示）。
- **采购对接人** = admin 在部门/组织架构中配置，系统自动带出，**提交者不选**。
- **标题** = 后端自动拼接：`【${titleType}】${projectName}_${MM}月${DD}日_${titleName}`，表单不显示，提交时生成。
- **编号** = `purq-YYYYMMDD-NNN`，后端生成，表单不显示。
- **总金额** = 所有明细 `amount` 之和，后端提交时算。
- **资金校验**：提交时后端校验 `总金额 ≤ 所选项目的剩余资金`，**超了直接拒绝申请**（不是拦截提示）。
- **审批流**：提交后进入审批，审批人 = 项目负责人 + 采购对接人（单批/群批按配置，节点到自己自动跳过）。都通过 → `approved`；任一拒绝 → `rejected`，退回申请人。

### 2.7 权限

| 操作 | 角色 | 说明 |
|---|---|---|
| 新增申请 | 所有登录用户 | 申请人=自己 |
| 查看 | 申请人看自己、负责人看所属项目、对接人看全量 | 数据权限 |
| 编辑/删除 | 申请人（仅 draft/rejected 状态） | |
| 提交审批 | 申请人 | draft → pending |
| 审批通过/退回 | 项目负责人 + 采购对接人 | 单批/群批按配置 |
| 导出 Excel | 申请人 + 对接人 + 采购专员 | 按中心模板 |

### 2.8 页面交互
- **列表页**：表格展示（编号、标题、项目、金额、状态、创建时间），按数据权限过滤；状态用不同颜色标签。
- **表单页**：
  - 顶部：标题类型（自购/对公）单选 → 控制下方字段显隐
  - 项目选择：树形下拉（展开区域→项目→子项），选后系统背后带出负责人与对接人（前端不显示或只读展示）
  - 标题名称：文本框
  - 明细区：可增删行表格，每行选分类树（科研/非科研 → 一级 → 二级叶子）→ 填品名规格等
  - 附件区：自购显示付款截图上传、对公显示报价单+开票信息
  - 底部：暂存草稿 / 提交审批
- **详情页**：只读展示全部信息 + 审批记录 + 流程图
- **Excel 导出**：按中心模板生成，文件名 = 标题 + 三位序数（避免重名）

## 页面三：采购验收

### 3.1 用途
采购到货后，按采购申请逐条明细验收：上传实物拍照图 + 发票，核对金额（一阶段人工核对，二阶段 AI 初审）。

> **验收逻辑与采购申请相似**：不是"三人各自验收"，而是同一个权限体系下，由验收操作人（对接人/项目管理员）按申请单逐明细验收，金额核对与流程都复用采购的套路。

### 3.2 数据库表（新增）
- 验收单：`pms_acceptance`
- 验收明细：`pms_acceptance_item`

### 3.3 验收单字段表

| 字段 | 数据库列 | 类型 | 来源 | 说明 |
|---|---|---|---|---|
| 验收ID | `id` | bigint | 系统生成 | 主键 |
| 验收编号 | `acceptance_code` | varchar(64) | **自动生成** | `acpt-YYYYMMDD-NNN` |
| 关联采购申请ID | `request_id` | bigint | **系统自动** | 从哪张申请来 |
| 项目ID | `project_id` | bigint | **自动带出** | 从申请单带出 |
| 验收操作人 | `operator` | bigint | **系统自动** | 当前操作人（对接人/项目管理员），采购同一套权限 |
| 验收日期 | `acceptance_date` | date | **用户填** | |
| 验收状态 | `status` | varchar(20) | **系统自动** | pending待验收/partial部分验收/finished已完成/rejected不合格 |
| 备注 | `remark` | varchar(500) | **用户填（可空）** | |
| 创建时间 | `create_time` | datetime | **系统自动** | |
| 删除标志 | `del_flag` | bigint | **系统自动** | |

### 3.4 验收明细字段表

> 一条采购明细对应一条验收记录。一张申请有 N 条明细 → N 条验收记录。

| 字段 | 数据库列 | 类型 | 来源 | 说明 |
|---|---|---|---|---|
| 验收明细ID | `id` | bigint | 系统生成 | 主键 |
| 验收单ID | `acceptance_id` | bigint | **系统自动** | 关联验收单 |
| 采购明细ID | `request_item_id` | bigint | **系统自动** | 关联哪条采购明细 |
| 品名 | `item_name` | varchar(200) | **自动带出** | 从采购明细带出，只读 |
| 规格型号 | `spec` | varchar(200) | **自动带出** | 只读 |
| 申请单价 | `apply_price` | decimal(12,2) | **自动带出** | 从采购明细的 `unit_price` |
| 发票金额 | `invoice_price` | decimal(12,2) | **用户填** | 该物料发票上的实际金额；一阶段人工填，二阶段 AI 提取 |
| 金额核对结果 | `price_check` | varchar(20) | **系统自动** | pass(发票≤申请)/over(发票>申请，冲红) |
| 实物图片 | `photo_url` | varchar(1000) | **用户传（必填）** | 实物拍照图，可多张 |
| 发票附件 | `invoice_url` | varchar(1000) | **用户传（必填）** | 对应发票，**一般是 PDF**（附件上传需支持 PDF/图片） |
| AI审核意见 | `ai_opinion` | text | 二阶段 | AI 核对金额，一阶段留空 |
| 验收结果 | `result` | varchar(20) | **用户选** | pass通过/over冲红(需重开发票或重新申请) |
| 备注 | `remark` | varchar(500) | **用户填（可空）** | |
| 删除标志 | `del_flag` | bigint | **系统自动** | |

### 3.5 业务规则
- **验收前提**：采购申请状态为 `approved`。
- **金额核对**：系统自动比对 `invoice_price` vs `apply_price`：
  - `invoice_price ≤ apply_price` → 正常通过（**可以比申请价低**）
  - `invoice_price > apply_price` → 标记"冲红"，提示需要重开发票或重新提交采购申请（**不能比申请价高**）
- **验收逻辑同采购**：不是三人各自验收，验收操作人 = 采购同一权限体系的对接人/项目管理员，一阶段一人操作即可。
- **验收完成后自动入库**：物料写入仓库，**入口保留商品全部信息（引用采购明细：品名/规格/链接/发票等）**，既可复购又可溯源。
- **AI 初审**（二阶段）：调用 Dify 服务核对发票上的金额与申请金额是否一致，一阶段人工填发票金额即可。

### 3.6 权限

| 操作 | 角色 |
|---|---|
| 发起/填写验收 | 采购对接人 / 项目管理员（采购同一套权限） |
| 查看 | 申请人 + 对接人 + 负责人 + 管理员 |

## 页面五：BOM 库

### 5.1 用途
管理"经过筛选、测试 OK 的物料"档案（≠仓库），以及 BOM 表（产品 → 任意层级结构，组 N 套出缺失单 → 联动采购）。

### 5.2 数据库表（新增，替换现有单张 `pms_bom_item`）
- BOM 物料库：`pms_bom_catalog`（物料档案库）
- BOM 表（产品）：`pms_bom_table`
- BOM 节点：`pms_bom_node`（**不限层级**，文件夹/文件式结构）

> **层级不必定死**：库对应多个表，每个表 = 一个产品。产品下面怎么划分**不限制层级**——一个产品拆多个部分，其中一个部分复杂就继续拆多个部分，下面的才对应具体商品。某个部分本身可能就是另一个产品（**复用**），类似"文件夹与文件"的关系；**不是所有叶子都在最底层**。

### 5.3 BOM 物料库字段表（`pms_bom_catalog`）

> BOM 库 = 物料档案库。和仓库的区别：仓库是"买过的"（含消耗品/一次性），BOM 库是"筛选测试 OK 的"（可复用、标准化）。

| 字段 | 数据库列 | 类型 | 来源 | 说明 |
|---|---|---|---|---|
| 物料ID | `id` | bigint | 系统生成 | 主键 |
| 品名 | `item_name` | varchar(200) | **用户填** | |
| 规格型号 | `spec` | varchar(200) | **用户填** | |
| 品牌 | `brand` | varchar(100) | **用户填** | |
| 单位 | `unit` | varchar(20) | **用户填** | |
| 参考单价 | `ref_price` | decimal(12,2) | **用户填** | |
| 分类 | `category` | varchar(50) | **用户选** | 材料/设备/其他等 |
| 产品链接 | `link` | varchar(500) | **用户填（可空）** | 关联产品链接 |
| 关联项目 | `project_id` | bigint | **用户选（可空）** | 关联项目 |
| 关联仓库库存 | `stock_id` | bigint | **用户选（可空）** | 模糊搜索关联仓库物料，关联后可显示库存余量 |
| 状态 | `status` | tinyint | **用户选** | 0停用 1正常 |
| 备注 | `remark` | varchar(500) | **用户填（可空）** | |
| 创建时间 | `create_time` | datetime | **系统自动** | |
| 删除标志 | `del_flag` | bigint | **系统自动** | |

### 5.4 BOM 表（产品）字段表（`pms_bom_table`）

> 一个 BOM 表 = 一个机械成品/仪器，如"全画幅结构光超分辨显微镜系统"。

| 字段 | 数据库列 | 类型 | 来源 | 说明 |
|---|---|---|---|---|
| BOM表ID | `id` | bigint | 系统生成 | 主键 |
| 产品名称 | `name` | varchar(200) | **用户填** | 如"SIM显微镜系统" |
| 规格型号 | `spec` | varchar(200) | **用户填（可空）** | |
| 关联项目 | `project_id` | bigint | **用户选（可空）** | 该产品属于哪个项目 |
| 状态 | `status` | tinyint | **用户选** | 0停用 1正常 |
| 备注 | `remark` | varchar(500) | **用户填（可空）** | |
| 创建时间 | `create_time` | datetime | **系统自动** | |
| 删除标志 | `del_flag` | bigint | **系统自动** | |

### 5.5 BOM 节点字段表（`pms_bom_node`，替代原"部分/零件"两张表）

> 用**一棵树**表达任意层级：文件夹=分组（如"电路部分"），文件=具体商品（关联 BOM 库物料）。文件夹可继续套文件夹；一个节点可以标记为"复用产品"（引用另一个 BOM 表）。

| 字段 | 数据库列 | 类型 | 来源 | 说明 |
|---|---|---|---|---|
| 节点ID | `id` | bigint | 系统生成 | 主键 |
| BOM表ID | `bom_table_id` | bigint | **系统自动** | 属于哪个产品 |
| 上级节点ID | `parent_id` | bigint | **用户选** | 0=顶层分组；非0=挂在某个分组下；**层级不限** |
| 节点类型 | `node_type` | varchar(20) | **用户选** | group分组(文件夹) / item商品(文件) / product引用产品 |
| 分组名称 | `group_name` | varchar(200) | **用户填（group时）** | 如"电路部分" |
| 关联BOM库物料 | `catalog_id` | bigint | **用户选（item时）** | 模糊搜索 BOM 库物料，选中后自动带出品名/规格/品牌/单位 |
| 品名 | `item_name` | varchar(200) | **自动带出** | 从 BOM 库带出，只读 |
| 规格 | `spec` | varchar(200) | **自动带出** | 只读 |
| 品牌 | `brand` | varchar(100) | **自动带出** | 只读 |
| 单位 | `unit` | varchar(20) | **自动带出** | 只读 |
| 单套用量 | `qty_per_unit` | decimal(10,2) | **用户填** | 组装1套需要几个 |
| 参考单价 | `ref_price` | decimal(12,2) | **自动带出** | 从 BOM 库带出 |
| 仓库库存 | `stock_qty` | decimal(10,2) | **系统实时查** | 关联了仓库物料时显示当前库存；未关联显示"未关联" |
| 引用BOM表ID | `ref_bom_table_id` | bigint | **用户选（product时）** | 复用另一个产品（整棵子树） |
| 排序号 | `sort_no` | int | **系统自动** | |
| 备注 | `remark` | varchar(500) | **用户填（可空）** | |
| 删除标志 | `del_flag` | bigint | **系统自动** | |

> **节点层级示例**：
> - SIM显微镜系统（BOM表）
>   - 电路部分（分组）
>     - 电路板 A（商品，关联 BOM 库）
>     - 电源模块（分组）→ 继续拆
>       - 电源芯片（商品）
>   - 光学部分（分组）
>     - 镜头（商品）
>   - 标准机箱（引用产品 → 复用"机箱"这个 BOM 表的整棵子树）

### 5.6 业务规则 — 物料核对（组 N 套出缺失单）

1. 用户在 BOM 表详情页输入"要组装 N 套"
2. 后端遍历该产品树下所有**商品节点**（含引用的产品子树），计算：
   - 需要量 = `qty_per_unit × N`
   - 库存量 = 关联仓库物料的 `qty_available`（未关联则视为 0）
   - 差额 = 需要量 - 库存量
3. 差额 > 0 的商品汇总成**缺失单**
4. 缺失单可：
   - **导出 Excel**
   - **一键生成采购申请**：自动把缺失的商品填入采购申请明细（品名/规格/品牌/单位/数量/单价全带好），用户确认后提交走审批流

### 5.7 BOM 库 vs 仓库 对照

| 维度 | 仓库 (`pms_warehouse_stock`) | BOM 库 (`pms_bom_catalog`) |
|---|---|---|
| 是什么 | 所有买过的物料 | 筛选测试 OK 的物料档案 |
| 来源 | 验收入库自动来 + 手动添加 | 人工筛选录入 |
| 含一次性消耗品 | 是 | 否 |
| 有库存数量 | 是（可用数量） | 否（是档案，不是库存） |
| 关联关系 | 关联采购明细 | 关联仓库物料（可选）+ 产品链接 + 项目 |

### 5.8 权限

| 操作 | 角色 |
|---|---|
| 查看 BOM 库/表 | 所有登录用户 |
| 新增/编辑/删除 BOM 库物料 | 管理员 + 采购对接人 |
| 新增/编辑/删除 BOM 表/节点 | 管理员 + 采购对接人 |
| 物料核对 + 生成缺失单 | 所有登录用户 |
| 缺失单转采购申请 | 所有登录用户（转成申请后走申请流程） |

## 附录二：自动生成 vs 用户填写 速查

### 全自动（用户完全不用管，表单不显示）
- 申请编号、项目编码、验收编号、合同编号、报销编号、领用编号
- 申请人 = 当前登录用户
- 创建时间、创建人、删除标志
- 流程实例ID
- 总金额（明细汇总）
- 入库日期（验收入库时自动）
- 流水记录（系统自动写）

### 选项目后自动带出（用户只选项目，其余系统背后做）
- 项目负责人 = `pms_project.leader`（前端默认不显示）
- 采购对接人 = admin 配置（部门/组织架构），前端默认不显示
- 验收单关联的申请信息 = 从申请单带出

### 用户填写
- 项目名称/预算/负责人/日期（项目管理，仅管理员）
- 自购/对公、标题名称、采购类型、明细全部字段、申请原因（采购申请）
- 付款截图（自购）/报价单+开票信息（对公）
- 发票金额、实物图、发票（PDF/图片）（验收）
- 领用数量、用途（领用申请）
- BOM 物料信息、产品结构（分组/商品/引用）、单套用量（BOM 管理）

## 附录三：阶段划分

### 一阶段（传统，当前做）
1. 项目管理（含资金管理，负责人权限联动）
2. 采购申请（自购/对公表单 + 明细 + 中心 Excel 导出）
3. 审批流（负责人 + 对接人，单批/群批，节点到自己自动跳过）
4. BOM 管理（产品 → 不限层级节点 + 组 N 套缺失单 + 联动采购申请）
5. 仓库（自动入库 + 手动添加 + 出库 + 领用申请 + 流水）
6. 流转记录
7. 验收（人工核对金额 + 实物图/发票 PDF 上传 + 自动入库）
8. 合同生成（模板渲染 + 导出）
9. 报销导出（打包 ZIP）

### 二阶段（AI + 外部对接）
- 链接扒型号/价格（Agent 内置浏览器）
- AI 验收初审（Dify 核对发票金额）
- AI 完善 BOM 库和 BOM 表字段
- 邮件发送报销包
- 中心 OA 对接（泛微）
- 采购对接人系统分配/算法推荐
