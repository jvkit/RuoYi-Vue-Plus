- **资金消耗归属**：通过 `pms_procurement_request.project_id` 关联项目，申请通过后 `used_amount` 累加，可按项目维度查看资金消耗明细。

### 2.6 业务规则
- **申请人** = 当前登录用户，后端 `LoginHelper.getUserId()` 自动写入 `create_by`，前端表单不显示此字段。
- **项目负责人** = 选项目后从 `pms_project.leader` 自动带出，只读显示。
- **采购对接人** = 目前固定（后端配置默认值），表单显示但只读；后续改为系统分配。
- **标题** = 后端自动拼接：`【${titleType}】${projectName}_${MM}月${DD}日_${titleName}`，表单不显示，提交时生成。
- **编号** = `purq-YYYYMMDD-NNN`，后端生成，表单不显示。
- **总金额** = 所有明细 `amount` 之和，后端提交时算。
- **资金校验**：提交时后端校验 `总金额 ≤ pms_project.used_amount 对应项目的剩余资金`，超了拦截。
- **审批流**：提交后同时通知项目负责人 + 采购对接人，两人都通过 → 状态变 `approved`；任一拒绝 → 状态变 `rejected`，退回申请人。

| 操作 | 角色 | 说明 |
|---|---|---|

| 编辑/删除 | 申请人（仅 draft/rejected 状态） | |
| 提交审批 | 申请人 | draft → pending |
| 审批通过/退回 | 项目负责人 + 采购对接人 | 并签 |
| 导出 Excel | 申请人 + 对接人 + 采购专员 | 按中心模板 |

### 2.8 页面交互
- **列表页**：表格展示（编号、标题、项目、金额、状态、创建时间），按数据权限过滤；状态用不同颜色标签。
- **表单页**：
  - 顶部：标题类型（自购/对公）单选 → 控制下方字段显隐
  - 项目选择：树形下拉（展开区域→项目→子项），选后自动带出负责人
  - 标题名称：文本框
  - 明细区：可增删行表格，每行选分类树（科研/非科研 → 一级 → 二级叶子）→ 填品名规格等
  - 附件区：自购显示付款截图上传、对公显示报价单+开票信息
  - 底部：暂存草稿 / 提交审批
- **详情页**：只读展示全部信息 + 审批记录 + 流程图
- **Excel 导出**：按中心模板生成，文件名 = 标题 + 三位序数（避免重名）

### 3.5 业务规则
- **验收前提**：采购申请状态为 `approved`。
- **金额核对**：系统自动比对 `invoice_price` vs `apply_price`：
  - `invoice_price ≤ apply_price` → 正常通过
  - `invoice_price > apply_price` → 标记"冲红"，提示需要重开发票或重新提交采购申请
- **三人验收**：验收单自动带出申请单的三人组，三人均需确认（一阶段简化为一人操作即可，但记录显示三人）。？？？其实不是三人验收，这里验收的和前面采购的逻辑蛮相似的
- **验收完成后**：物料可入库（自动或手动，见仓库页面）。？？？无疑问就是自动入库，并且入口保留商品全部信息，其实应该就是引用，到时候可以看到最粗的比如采购时填的链接，发票什么的，这样既可以复购又可以溯源
- **AI 初审**（二阶段）：调用 Dify 服务核对发票图片上的金额与申请金额是否一致，一阶段人工填发票金额即可。

### 5.7 业务规则 — 物料核对（组 N 套出缺失单）

1. 用户在成品详情页输入"要组装 N 套"
2. 后端遍历该成品下所有零件，计算：
   - 需要量 = `qty_per_unit × N`
   - 库存量 = 关联仓库物料的 `qty_available`（未关联则视为 0）
   - 差额 = 需要量 - 库存量
3. 差额 > 0 的零件汇总成**缺失单**
4. 缺失单可：
   - **导出 Excel**
   - **一键生成采购申请**：自动把缺失的零件填入采购申请明细（品名/规格/品牌/单位/数量/单价全带好），用户确认后提交走审批流

### 5.8 BOM 库 vs 仓库 对照

| 维度 | 仓库 (`pms_warehouse_stock`) | BOM 库 (`pms_bom_catalog`) |
|---|---|---|
| 是什么 | 所有买过的物料 | 筛选测试 OK 的物料档案 |
| 来源 | 验收入库自动来 | 人工筛选录入 |
| 含一次性消耗品 | 是 | 否 |
| 有库存数量 | 是（可用/在途） | 否（是档案，不是库存） |
| 关联关系 | 关联采购明细 | 关联仓库物料（可选） |

## 附录二：自动生成 vs 用户填写 速查

### 全自动（用户完全不用管，表单不显示）
- 申请编号、项目编码、验收编号、合同编号、报销编号、领用编号
- 申请人 = 当前登录用户
- 创建时间、创建人、删除标志
- 流程实例ID
- 总金额（明细汇总）
- 入库日期（验收入库时自动）
- 流水记录（系统自动写）

### 选项目后自动带出（用户只选项目，其余只读）
- 项目负责人 = `pms_project.leader`
- 验收单的三人组 = 从申请单带出

### 系统固定（一阶段固定，后续改自动分配）
- 采购对接人 = 配置默认值

### 用户填写
- 项目名称/预算/日期（项目管理）
- 自购/对公、标题名称、采购类型、明细全部字段、申请原因（采购申请）
- 付款截图（自购）/报价单+开票信息（对公）
- 发票金额、实物图、发票图（验收）
- 领用数量、用途（领用申请）
- BOM 物料信息、单套用量（BOM 管理）

## 附录三：阶段划分

### 一阶段（传统，当前做）
1. 项目管理（含资金管理）
2. 采购申请（自购/对公表单 + 明细 + 中心 Excel 导出）
3. 两级并签审批流（负责人 + 对接人同时审）
4. BOM 管理（成品→部分→零件 + 组 N 套缺失单 + 联动采购申请）
5. 仓库（入库 + 出库 + 领用申请 + 流水）
6. 流转记录
7. 验收（人工核对金额 + 实物图/发票上传）
8. 合同生成（模板渲染 + 导出）
9. 报销导出（打包 ZIP）

### 二阶段（AI + 外部对接）
- 链接扒型号/价格（Agent 内置浏览器）
- AI 验收初审（Dify 核对发票金额）
- AI 完善 BOM 字段
- 邮件发送报销包
- 中心 OA 对接（泛微）
- 采购对接人系统分配/算法推荐
