# 采购模块迁移报告：5.6.2 → 6.0.0（ruoyi-6x / plus-ui-6x）

> 汇报对象：老板 / 产品负责人
> 日期：2026-08-11

## 一、背景与结论

为评估未来升级，将生产版 `RuoYi-Vue-Plus` 5.6.2 中已重构的**采购模块**（`ruoyi-procurement` + 前端 `views/procurement` / `api/procurement`）**原样迁移**到 6.0.0 参考版（后端 `ruoyi-6x` + 前端 `plus-ui-6x`），并验证通过。

**本次范围**：采购模块完整迁移（项目、供应商、BOM、采购申请含 Warm-Flow 工作流、采购订单）。**发票模块 `ruoyi-invoice` 本次不迁移**（按老板要求，只做采购）。

**运行方式**：6x 走独立数据库 `ry-vue-6x` + 独立端口，与 5.6.2 生产完全隔离，可随时回退。

## 二、6.x 与 5.6.2 的主要差异（迁移背景）

| 维度 | 5.6.2 | 6.0.0 |
|---|---|---|
| JDK / Spring Boot | 17 / 3.5.15 | 21 / 4.1.0 |
| 多租户 | 有（`TenantEntity`） | **移除** |
| 分页返回 | `TableDataInfo` | `PageResult` |
| Excel | FastExcel（`cn.idev.excel`） | **fesod-sheet**（`org.apache.fesod.sheet`） |
| 幂等注解 | `common-idempotent` | `common-redis` |
| 工作流契约 | `common.core.service.WorkflowService` | `ruoyi-api` 的 `workflow.api.WorkflowService` |
| 基础字段 | `BaseEntity` 含 `params` | `BaseEntity` 删除 `params`，时间改 `LocalDateTime` |

两套代码**无共同 Git 祖先**，无法 merge，只能按新结构移植。

## 三、迁移内容

### 1. 后端（`ruoyi-6x/ruoyi-modules/ruoyi-procurement/`）
- 复制整套源码（controller/domain/bo/vo/mapper/service + 3 个 XML）。
- pom：删 `ruoyi-common-tenant`、`ruoyi-common-idempotent`，加 `ruoyi-api`。
- 接入：加入 `ruoyi-modules/pom.xml`、`ruoyi-admin/pom.xml`、根 pom `dependencyManagement`。

### 2. 后端代码适配
- **去多租户**：5 个主表实体继承 `TenantEntity`→`BaseEntity`，去掉 `tenant_id`。
- **`TableDataInfo`→`PageResult`**：5 个 controller 的 list 返回 `R<PageResult<T>>`，service 用 `PageResult.build(records, total)`。
- **Excel 换库**：controller 导出改 `ExcelBuilder.of(...).sheetName(...).toResponse(...)`；全部 VO 的 `@ExcelProperty` 包改为 `org.apache.fesod.sheet`。
- **`BaseEntity.params` 删除**：给用到 `getParams()` 或 XML 里 `bo.params.beginCreateTime` 的 5 个 BO 补回 `params` 字段（空 HashMap）。
- **包路径搬家**：`WorkflowService`/`StartProcessDTO`/`ProcessEvent`/`ProcessDeleteEvent`→`org.dromara.workflow.api.*`；`@RepeatSubmit`→`org.dromara.common.redis.annotation`。
- **`DateUtils.getCurrentDate()` 不存在**：改 `LocalDate.now().format(...)` 生成单号。

### 3. 前端（`plus-ui-6x/src/views/procurement/` + `api/procurement/`）
- 复制 5 个页面 + api。
- 适配：`AxiosPromise` 导入改 `@/utils/api-types`；分页回填 `res.rows`→`res.data.rows` / `res.total`→`res.data.total`。
- dev 代理指向 6x 后端 8091、dev 端口 8082。
- 修复 6x 快照自带的大小写 bug：`api/monitor/logininfo`→`loginInfo`。
- **运行时适配（白屏修复，`src/plugins/index.ts`）**：
  - 补注入 `animate`：旧版页面用 `proxy.animate.searchAnimate`，6x 有 `animate.ts` 但上游未注入 → 补 `app.config.globalProperties.animate = animate`。
  - 补注入旧版全局方法：`parseTime/handleTree/addDateRange/selectDictLabel/selectDictLabels/useDict/getConfigKey/updateConfigByKey`（6x 刻意不注入，旧版页面依赖）。
- **登录适配（`src/views/login.vue`）**：关闭后端验证码后 `captchaEnabled=false`、验证码框消失，但 `loginRules.code` 的 required 校验仍在导致登录被卡 → 改为未启用验证码时跳过表单校验直接登录。

### 4. 数据库（`ruoyi-6x/script/sql/procurement_6x.sql`，已导入 `ry-vue-6x`）
- 建表 7 张（`pms_project/supplier/bom_item/procurement_request(+item)/purchase_order(+item)`），**去掉 `tenant_id`**。
- 菜单 + 按钮权限：6.x 雪花 BigInt id（1801xxx 段），去掉租户，补 `active_menu/ext/create_dept`，`create_by` 用 admin 雪花 id。
- 字典 `pms_purchase_type`：雪花 id（1802xxx/1803xxx）。
- Warm-Flow 流程定义 `pms_request`（沿用 tenant_id `000000`）。
- 中文编码验证无误。
