## 一、Langfuse 自托管与接入

### 背景
用户确定 Langfuse 走**自托管**（MIT 开源、本地免费全功能），放弃 langfuse 云版与 LangSmith/LangGraph。自托管在 `agents/langfuse/`，docker-compose 定制，**端口隔离**：存储组件（postgres/clickhouse/redis/minio 内网）避开宿主机 3306/6379/9000 冲突，只暴露 Web 3000 和 MinIO 9092。

### 踩坑与解决
| 问题 | 解决 |
|---|---|
| 宿主机 docker-compose 是 1.29 旧版 | 用 `docker-compose`（非 `docker compose`），改配置必须 `down` 再 `up -d` |
| ClickHouse 报 "no Zookeeper configuration" | 加 `CLICKHOUSE_CLUSTER_ENABLED: "false"` |
| init 初始化邮箱被拒 | `admin@langfuse.com`（不能用 `.local` TLD） |
| langfuse Python SDK 4.x 是 OTel-native，**没有 `trace()`** | 用 `start_as_current_observation(name, trace_context, as_type)` 同步 with 上下文 |
| trace_id 12 位被忽略 | 改成 `uuid.uuid4().hex`（32 位小写 hex） |

### 落地成果
- `core/langfuse.py` 重写：导出 `trace()` 异步上下文管理器（未配置时退化为 no-op 不抛错）+ `get_prompt()`（langfuse 优先，失败回退源码默认值）
- 提示词 `invoice_extract` 已同步进 langfuse v1，**改提示词无需改代码**，网页发布新版本即生效
- 验证：最小 trace 落库 ✅、get_prompt 拉取 langfuse 版 ✅、**真实识别 trace 完整落库**（input/output 可见，用于区分程序问题 vs AI 问题）✅
- 登录信息：`http://localhost:3000`，admin@langfuse.com / Langfuse@12345

## 二、发票 AI 批量识别匹配（首个单步智能体业务）

### 设计思路
分层架构：**代码做确定性的脏活，AI 只做认知节点**。
- 程序：PDF 第一页转图、图片压缩、商品名归一化匹配、金额核对、报告生成
- AI：只"看图 → 输出结构化字段"，**不做任何业务判断**（是否冲红、是否超标、属于哪个商品都由程序算）

技术栈：FastAPI + pydantic-ai 2.36.0 + Langfuse（litellm 已从代码中移除，dify 已弃用）。

### 全链路效果（Playwright 实测）
4 张 mock 发票 + 3 明细采购申请，拖入后：

| 明细 | 发票单价 | 附件 | 标记 |
|---|---|---|---|
| GPU服务器 | 100000.00 | 自动上传 ✅ | 通过 |
| 显示器 | 1500.00（单价，非合计） | 自动上传 ✅ | 通过 |
| 工控机 | 负数 | 自动上传 ✅ | **冲红** |
| 打印机（外来） | — | **不自动上传** | — |

报告：
```
✅ 发票「good_invoice_gpu.pdf」→ 商品「GPU服务器(A100-80G)」
✅ 发票「good_invoice_monitor.pdf」→ 商品「显示器(27英寸4K)」
🔴 发票「red_invoice_controller.pdf」为冲红发票，已匹配商品「工控机(IPC-610)」
❌ 发票「external_printer.pdf」不属于本订单，未匹配到商品
```
并支持**多轮上传**：只把未填发票金额的明细送匹配，传少了可再补。

### 过程中修复的真实问题
1. **mock 发票没有商品明细行** → 匹配永远跑不通（这是之前反复"外来票"的根因），已重新生成带明细的测试图
2. **后端 `ai-invoice-match` 没进 jar** → 后端跑的是旧 jar，接口从未编译进去，重新打包并重启
3. **金额口径 bug** → 之前回填整票合计导致显示器被误判超标，改为回填**单价**并逐商品核对
4. **红字漏判** → AI 偶发不设 is_red，加程序兜底（单价为负即判冲红），3 连稳定
5. **多张附件上传被防重复拦截** → RuoYi 前端 request.ts 对同 URL 连续 POST 拦第二次，已加 `repeatSubmit: false`
6. **AI 偶发失败** → 加 `retries=1`，避免单张票偶发失败被误判无效
