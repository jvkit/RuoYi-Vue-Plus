# 采购系统第一阶段实施方案（传统表单版）

> 范围：先做**纯传统**流程，不做 AI、不做自动邮件、不做链接扒价、不做供应商管理。
> 目标：打通「采购申请 → 两级审批 → BOM → 仓库缺失单 → 联动采购」主线闭环，页面/接口可独立验证。

---

## 第一阶段功能清单

| # | 功能 | 说明 |
|---|---|---|
| 1 | 采购申请（传统表单） | 申请人=提交者，负责人/对接人审批 |
| 2 | 两级审批流 | 负责人 → 对接人 |
| 3 | BOM 管理 | 成品 → 部分 → 零件 三级 |
| 4 | 仓库 + BOM-仓库联动 | 模糊搜索、是否在库、组 N 套出缺失单 → 联动采购 |
| 5 | 中心 Excel 导出 | 模板对齐，无供应商字段 |

---

## 功能 1：采购申请（传统表单）
- 复用 `pms_procurement_request(_item)`。
- 申请人 = 当前登录用户（后端自动，`LoginHelper.getUserId()`），无需填。
- 项目（树形下拉）→ 带出项目负责人。
- 自购/对公 `titleType`；科研/非科研单选 → 一级展开选二级（900 无叶子即自身）。
- 明细：品名/规格/品牌/单位/数量/单价/链接，金额自动汇总。
- 三人组：申请人自动、负责人=项目 leader 自动、对接人=申请人选。
- 系统自动：标题拼接【自购/对公】+项目名+月日+名称、编码 `purq-日期-序号`、金额汇总。

## 功能 2：两级审批流
- 在现有 `pms_request` 流程改为：提交 → 项目负责人审批 → 采购对接人审批 → 结束。
- 负责人=项目 leader（流程变量），对接人=申请单对接人（流程变量）。
- 任一级可退回申请人，退回后可改单重提。

## 功能 3：BOM 管理（成品→部分→零件）
- 新增三级表（替代单张 `pms_bom_item`）：
  ```
  pms_bom_table      成品：id, name, spec, remark
  pms_bom_part       部分：id, bom_table_id, part_name, sort_no
  pms_bom_part_item  零件：id, bom_part_id, item_name, spec, brand, unit,
                      qty_per_unit(单套数量), stock_id, remark
  ```
- 页面：BOM 成品列表 → 点入成品见全部细节（部分+零件树）→ 整体编辑 / 点进某部分单独编辑其零件。

## 功能 4：仓库 + BOM-仓库联动
- 新增仓库库存表 `pms_warehouse_stock`：item_name/spec/brand/unit/qty_available/…。
- BOM 零件模糊搜索关联仓库物料（stock_id），零件显示「是否在库 / 余量」。
- 成品页「物料核对」：输入套数 N → 后端按 `qty_per_unit × N` 对照库存 → 标记足够/不足 → 不足汇总成缺失单 → 导出 Excel → 一键联动生成采购申请（自动带明细）→ 确认后提交走审批流。

## 功能 5：中心 Excel 导出
- 按中心真实模板导出，文件名=标题+三位序数去重；无供应商/平台字段。
