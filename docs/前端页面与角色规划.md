# 前端页面与角色规划

> 目标：说清楚每个角色进入系统后「点什么、填什么、系统自动帮你做什么」，并梳理页面量、如何靠权限减少重复开发，以及每个人的个性化填表方案。
> 前置：业务方案见《采购系统扩展方案.md》。本文档规划页面结构，落地在 `plus-ui-6x`。

---

## 一、角色划分（谁看什么、谁能做什么）

沿用 RuoYi 的角色 + 菜单/按钮权限 + 数据权限体系。新增角色（后续建角色时配权限字符）：

| 角色 | 一句话职责 | 核心权限 |
|---|---|---|
| 采购申请人（内部/外部员工） | 提采购申请、传凭证、看自己申请进度 | `procurement:request:*`（仅自己的数据）|
| 采购对接人 | 审申请、转订单、对公合同、分供应商 | 订单 + 申请审批 + 合同 |
| 项目负责人 | 审批所属项目的申请、看预算/进度 | 申请审批（数据权限限自己项目）|
| 仓库看管人 | 入库、审领用、管理库存 | 仓库/库存/出入库 |
| 采购专员 | 报销打包发送、汇总 | 报销 + 导出 |
| 系统管理员 | 分类树、BOM 维护、偏好模板、菜单字典 | 全部 |

> 关键点：**一个业务实体一套页面**，不按角色复制。角色差异靠「按钮权限 + 数据权限 + 字段显隐」三招实现（见第三节），页面量不随角色数增长。

## 二、每个角色：操作路径 / 填什么 / 系统自动做什么

### 1. 采购申请人（内部员工 + 工作室外部申请人）
**入口**：首页 → 采购申请 → 我的申请
- **填**：选项目（树形）、自购/对公、科研/非科研分类（一级展开选二级，900 无叶子即自身）、品名/规格/品牌/单位/数量/单价、商品链接；合同/对公上传报价单、淘宝类上传付款截图。
- **系统自动做**：标题拼接【自购/对公】+项目名+月份日+名称；编码 `purq-日期-三位序号`；金额=单价×数量汇总；明细级供应商由链接自动识别平台。
- **提交后**：流程自动流入「采购对接人 + 项目负责人」审批。申请人只看到自己的单，无审核按钮。

### 2. 采购对接人
**入口**：待我处理 → 采购申请（数据权限：分配给我的）
- **做**：审核申请（通过/退回）、把通过的单转成采购订单、分配/确认供应商、对公时生成采购合同（模板渲染开票信息+规格+数量+单价）、确认报价单/付款截图。
- **系统自动做**：订单编码、订单金额带出申请明细、合同从申请关键信息生成。

### 3. 项目负责人
**入口**：待我处理 → 采购申请（数据权限：我负责的项目）
- **做**：审批所属项目的申请、查看项目预算占用。
- **系统自动做**：待办聚合到统一入口，审批后状态流转。

### 4. 仓库看管人
**入口**：仓库 → 库存 / 出入库 / 领用审批
- **做**：验收后的物料入库（或系统自动入库）、审批领用申请、登记出库。
- **系统自动做**：入库扣减待验收/在途，出库扣库存、写流水。

### 5. 采购专员
**入口**：报销
- **做**：选择报销的单据 → 导出采购申请表 + 对应验收图 + 发票 → 打包压缩 → 邮件发送中心采购专员（外部）。
- **系统自动做**：按申请自动归集验收图/发票、按模板导出、文件名+序数去重、打包。

### 6. 系统管理员
**入口**：系统管理 / 采购配置
- **做**：维护采购分类树、BOM 库/产品线、偏好模板、字典、菜单、角色权限。
- **系统自动做**：无。

## 三、页面量清单 与 复用策略（如何减少工作量）

### 页面量（.vue 总数，约 14 个）

| 模块 | 页面 | 说明 |
|---|---|---|
| 项目 | 项目列表（含区域树） | 树形 CRUD |
| 采购申请 | 申请列表 | 数据权限过滤 |
| 采购申请 | 申请表单 | 明细表格 + 分类树 + 链接 + 上传 |
| 采购申请 | 申请详情 | 只读 + 审批记录/流程 |
| 采购订单 | 订单列表 / 订单表单 | 由申请转单 |
| 供应商 | 供应商列表 | CRUD |
| 采购分类 | 分类树配置（管理端） | 树形维护 |
| BOM | BOM 库 + 产品线 | 库表拆分维护 |
| 验收 | 验收列表 + 验收页 | 上传图/发票 + AI 核对 |
| 仓库 | 库存列表 | 含出入库记录 |
| 仓库 | 领用申请（列表+表单） | 申请人提交 + 看管人审批 |
| 报销 | 报销列表 | 打包发送 |
| 合同 | 合同列表 | 生成/查看 |
| 个人 | 我的填表方案 | 个性配置 |

**为什么是 14 个而不是"每人一套"**：复用靠以下三招——

1. **按钮权限（`v-hasPermi`）**：同一页面，申请人没有「审核/删除/导出」按钮，对接人有。后端 `@SaCheckPermission` 兜底。
2. **数据权限（`@DataScope`）**：申请人只看自己（`user_id`），对接人看分配给他的，负责人看自己项目。**同一列表页，不同角色看到不同数据**，不用分开页面。
3. **字段/分类显隐（`v-if`）**：表单里按「自购/对公」「科研/非科研」「是否有叶子」动态显隐字段；按角色显隐字段（如内部申请人才填内部申请人，外部申请人填对接人）。

> 结果：**页面量 ≈ 业务实体数，与角色数无关**。加角色只需配权限，不新增页面。

## 四、个性配置（每人可设定自己的偏好 / 多套方案）

需求：每个人可以保存自己常用的填表信息，后续填表按这个自动带出，且可配多套方案。

### 方案设计
- **新增表 `pms_user_form_scheme`**（用户填表方案）：
  ```
  id, user_id, scheme_name(方案名，如"科研材料-常用"), default_flag(是否默认), is_default,
  content_json(偏好内容 JSON), create_by, create_time, update_time
  ```
- `content_json` 存偏好键值，例如：
  ```json
  {
    "titleType": "对公",            // 自购/对公
    "purchaseType": "科研类",        // 科研/非科研
    "projectId": 123,               // 默认项目
    "category1": "100材料",
    "category2": "101金属材料",
    "items": [                      // 常用品名/规格/品牌，新增明细时一键带入
      {"itemName":"不锈钢板","spec":"304 1.5mm","brand":"","unit":"张","unitPrice":"80"}
    ],
    "invoice": {"抬头":"...", "税号":"..."},      // 开票信息
    "contact": {"对接人":"...", "收货地址":"..."}  // 联系人/地址
  }
  ```
- **前端**：个人中心「我的填表方案」CRUD 多套方案（可设默认）。
- **填表时**：表单顶部「套用方案」下拉 → 选中即自动带出对应字段，明细可批量插入常用品名。

### 落地要点
- 方案存后端表，**跨设备/换浏览器生效**（比 localStorage 可靠）。
- 首次进入可提示「从上次申请复制」，形成渐进式个性化。
- 默认方案填表自动加载，无需每次手选。
